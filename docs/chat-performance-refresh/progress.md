# 聊天性能与流畅度优化进度

## 当前状态

进行中。

第一阶段聚焦：

1. 首屏进入更稳。
2. 长会话滚动更顺。
3. 消息正文与 meta/复制/次级块不再错位。

## 已完成

1. 本地问题证据确认：
   - 全量富内容渲染
   - 首屏滚动初始化过重
   - 消息宽度与 meta 结构不稳定
2. `QClaw` 解包参考完成，并确认其价值主要在结构策略，不在像素复制。
3. 建立本 feature 文档。
4. 第一阶段结构改造已开始落地：
   - `use-stick-to-bottom-instant` 去掉隐藏滚动区的初始化策略
   - 消息行拆成主列与次级轨
   - 聊天消息宽度规则改成统一列系统，不再在组件里写两套硬编码 `max-w`
5. 根据 review 收口了风险点：
   - 不再对整条消息行使用 `content-visibility`
   - 仅对次级块、图片卡、文件卡、代码块使用更保守的离屏减重
   - 新增 `use-stick-to-bottom-instant` 行为测试
   - 聊天图片显式使用 `loading="lazy"` 与 `decoding="async"`
6. 新增渲染稳定性优化：
   - `Chat` 中的 `assistantAvatar` 已稳定化
   - 现有消息在父组件无关重渲下不会整片重新渲染
7. 第二轮低风险减载已落地：
   - 聊天图片增加 `loading=\"lazy\" + decoding=\"async\"`
   - 次级块、媒体卡片、代码块增加 `content-visibility` 和 `contain-intrinsic-size`
8. 输入区相关的人性化按钮继续收口：
   - “回到底部”按钮不再占据聊天区与输入区之间的一整行
   - 按钮改成依附输入区外层的浮层，不再靠正常文档流撑出空白
9. 聊天主区补回 IM 底部锚定规则：
   - 消息较少时，消息内容会自然贴着输入区，不再悬在顶部留下大块白洞
   - 固定的是整块聊天画布，不是把消息容器缩成内容高度
   - 这次修的是布局结构，不是表层间距补丁
