# 全局主题重构设计

## 背景

当前 `XClaw` 的问题，不是“颜色还不够好看”，而是整体仍然按网页产品的方式在组织界面：

- 底色、发光、渐变和卡片语义仍偏 `AI SaaS`
- 搜索框、侧栏、列表、输入区等核心控件仍偏 web component 语法
- 品牌色被用来承担过多视觉面积，导致界面发热、发飘
- 即使局部页面已经收平，整体壳层仍不像工业级桌面应用

这说明旧设计主线仍然偏“品牌主题方案”，而不是“桌面产品视觉系统方案”。

本轮设计重写后的核心结论是：

> **以 `QClaw` 为桌面基底，以 `XClaw` 为品牌点缀。**

更具体地说：

- `QClaw` 负责提供桌面应用的基底语言：色系、边界、source list、toolbar、搜索 trigger、字体、hover/active 语义
- `XClaw` 只保留自己的品牌识别：logo、主操作、焦点、少量激活态与状态点

目标不是做一个“像 QClaw 的 XClaw”，而是做一个**没有网页感、保留 XClaw 品牌辨识度的工业级桌面应用**。

## 设计总纲

### 最高准则

全局主题的最高准则正式固定为：

> **全局只保留一套冷中性 desktop substrate。**

解释：

- 这不是为了“模仿 QClaw 的外观”
- 这是吸收它已经被真实源码验证过的正确桌面基底规律
- `XClaw` 的品牌只作为 accent 挂在这套基底上，而不是重新发明第二套壳层

这条准则优先级高于“某个页面更好看”“某个模块想更有品牌感”这类局部判断。  
只要某个方案会破坏冷中性 substrate，就算局部更亮眼，也必须判定为错误方向。

### 新主线

新的主题主线定义为：

- **Substrate（基底）**：全面向 `QClaw` 的桌面壳层语法对齐
- **Accent（点缀）**：保留 `XClaw` 的深红铜品牌语气，但只在少数位置出现

一句话概括：

> **QClaw substrate, XClaw accent**

它的准确含义是：

- 学的是 `QClaw` 的桌面基底规律
- 不是复制它的品牌、图标、像素皮
- `XClaw` 仍然保留自己的 logo、品牌铜红和产品语气

### 不再采用的旧思路

以下思路正式废弃：

- “先定品牌主色，再扩散到页面”
- “通过暖色浅底 + 铜红 glow 做质感”
- “通过大卡片、厚搜索框、玻璃面板做桌面感”
- “每个页面单独长出一套更好看的壳”

这些都是网页设计思维，不是桌面产品设计思维。

## 参考与证据

### QClaw 已确认值得吸收的部分

基于本机解包的 `QClaw.app` 样式证据，确认以下点成立：

- 侧栏底色接近 `#fafafa`
- 搜索入口接近 `#f5f5f5`
- hover 接近 `#f0f0f0`
- 分割线接近 `#e5e5e7`
- 侧栏宽度约 `250px`
- source list 行高约 `40px`
- 列表默认是一行文本，不依赖头像、副标题、时间
- hover / active 非常轻
- 更多动作默认隐藏
- 字体走系统无衬线栈，而不是设计型 serif

这些不是风格偏好，而是已经存在的真实实现证据。

### 不直接照抄的部分

以下部分不直接复制：

- 不复制 `QClaw` 的 logo、品牌资产和像素皮
- 不完全复制它的搜索弹层策略
- 不为了模仿而牺牲 `XClaw` 当前更有价值的多 Agent 可辨识度
- 不复制它所有颜色值，而是复制它的**桌面层级逻辑**

## 目标

- 从根上去掉网页感和 AI SaaS 感
- 建立工业级桌面应用的浅色/深色视觉系统
- 让 `TitleBar / Sidebar / Source List / Workspace / Composer` 先像桌面应用
- 让品牌色退回点缀层，而不是背景层
- 让字体、边界、hover、选中态、搜索、列表、输入框统一到同一套桌面语法
- 保持一套统一品牌主题，只做轻度 mac / Windows 适配

## 非目标

- 不做像素级复刻 `QClaw`
- 不做两套独立的 mac / Windows 主题
- 不把所有页面都做成完全一致的视觉密度
- 不为了“去网页感”而去掉所有品牌感
- 不引入高饱和 AI 配色、厚 glow、大片渐变或伪拟态玻璃

## 设计原则

### 1. 先做桌面基底，再加品牌

视觉建立顺序必须固定：

1. 壳层与基底
2. 列表与导航语法
3. 输入与操作控件
4. 页面内容层
5. 品牌 accent

不能反过来。

### 2. 品牌色只做点缀，不做背景

深红铜只允许出现在：

- logo 识别
- 主按钮
- 焦点态
- 当前激活态的小面积强调
- 状态点和少量关键图标

禁止出现在：

- 大面积页面背景
- 整块侧栏底色
- 常规卡片底色
- 常规列表 hover 底色
- 普通输入框和普通分组标题

### 3. 桌面感来自结构，不来自特效

真正的桌面感来自：

- 冷中性基底
- 轻分界
- 稳定 source list
- 工具栏/标题栏/工作区的层级
- 搜索 trigger 化
- 默认隐身的次级动作

而不是来自：

- glow
- 大圆角卡片
- 厚表单
- 大面积渐变
- 彩色头像

### 4. 默认轻，激活才抬

默认状态必须足够安静：

- hover 才轻微显现
- active 才真正抬起
- destructive / runtime / warning 只在需要时明确出现
- 更多按钮、删除按钮、复制按钮等默认弱化或隐藏

### 5. 一页只有一个主角

任何页面都必须只有一个主焦点：

- 聊天页主角是消息和输入
- 聊天列表主角是当前会话轨
- 频道页主角是当前配置工作区
- 设置页主角是当前设置分区

其余元素只能做辅助。

## 主题结构

### 1. Substrate 层

这是桌面基底层，必须最大程度对齐 `QClaw` 逻辑。

硬约束：

- 所有高频页面必须共享同一套 substrate
- 不允许聊天页一套、频道页一套、设置页再一套
- 如果某个页面需要特殊视觉，必须建立在同一套 substrate 之上

#### 浅色

- `background`: 冷白灰
- `chrome`: `#fafafa` 一档
- `surface-filter`: `#f5f5f5` 一档
- `surface-hover`: `#f0f0f0` 一档
- `divider`: `#e5e5e7` 一档
- `foreground`: 深石墨灰

要求：

- 不再保留暖米色主基底
- 不再保留整页暖色 glow
- 不再保留明显 radial mesh 气氛层

#### 深色

- 深石墨底
- 中性灰分层
- 少量铜红焦点
- 强调边界和可读性，而不是大面积发光

要求：

- 不做 dashboard 式紫黑科技风
- 不做亮边玻璃盒子

### 2. Accent 层

`XClaw` 的品牌只保留在以下区域：

- 品牌 logo 与少量品牌字标
- 主 CTA
- 焦点 ring
- 当前项的轻激活态
- 状态点、微图标、少量高价值反馈

使用预算：

- 单页高显色面积不超过主视觉区的 `8%-10%`
- 如果一页肉眼看上去“铜红很多”，就是超预算

## 字体策略

字体必须全面回归系统无衬线栈，并以本机解包后的 `QClaw` 真源码为准，不再靠截图去猜 `SF Pro` 双栈。

已确认的源码证据来自：

- `.reference/qclaw-unpacked-20260321/out/renderer/assets/a-DBAJBZ7e.css`
- 其中全局 `body` 明确使用单一系统 sans 栈，而不是正文/标题分离的 `SF Pro Text / SF Pro Display`

### 默认字体

- `-apple-system`
- `BlinkMacSystemFont`
- `Segoe UI`
- `Roboto`
- `Oxygen`
- `Ubuntu`
- `Cantarell`
- `Fira Sans`
- `Droid Sans`
- `Helvetica Neue`
- `sans-serif`

### 规则

- 正文、标题、列表、按钮、输入框统一使用系统无衬线
- `XClaw` 继续保留 `font-display` 这样的语义 token，但它的值必须与 `QClaw` 源码里的全局系统 sans 栈一致，不能再伪造第二套展示字栈
- serif 标题、设计型 italic 品牌字、网页 editorial 风字体全部退出主产品界面
- `font-mono` 只保留给代码、ID、日志、配置 ref

## 组件语法

### 1. TitleBar

- 更像系统标题栏，而不是页面头图
- 只承担窗口/轻动作/极少量状态
- 不承担大标题展示

### 2. Sidebar / Rail

- rail 和侧栏必须视为同一导航壳层
- 不应是“两块拼起来的网页栏”
- 分隔靠极轻边界，不靠多层阴影和渐变

### 3. Source List

会话列表、部分导航列表、轻目录列表统一向 source list 靠拢：

- 单行优先
- 默认无时间
- 默认无头像
- 默认无副标题
- hover 轻
- active 轻
- 更多动作默认隐藏

### 4. Search

- 搜索入口应更像 filter trigger，而不是厚输入框
- 只有聚焦后才更像输入组件
- 默认状态必须安静

### 5. Input / Composer

- 输入框必须像内嵌编辑面板，而不是网页表单
- 工具按钮语义统一
- 状态贴近操作源头
- 正常态不播报基础设施细节

### 6. Message / Meta / Process Rail

- 助手消息更像文稿流
- 用户消息只保留轻 tint
- `thinking / tool / status / error` 统一成轻轨
- 次级动作只在 hover/focus/异常时抬起

## 页面落地原则

### 优先级 1：应用壳层

- `globals.css`
- `MainLayout`
- `TitleBar`
- `Sidebar`
- `Workspace`

### 优先级 2：聊天主路径

- 会话列表
- 消息区
- 输入区
- 错误/状态/快速动作

### 优先级 3：高频工作区

- Channels
- Settings
- Models
- Agents

### 优先级 4：其余页面

- Skills
- Cron
- Setup

## 平台适配

### mac

- 更轻
- 更静
- 边框更弱
- 阴影更短

### Windows

- 对比略高
- 分层略更明确
- 边界略更清楚

规则：

- 只允许 overlay 差异
- 不允许长出两套产品视觉

## 开发准则

- 必须以真实证据决定是否吸收 `QClaw` 设计，不得为了“像”而盲抄
- 先质疑“这个问题是不是结构问题”，再决定是否改配色
- 小型低风险 UI 微调允许敏捷直改，但前提是明确不触碰协议、状态链、滚动契约和跨组件数据流
- 任何声称“更像桌面 app”的改动，都必须同时核对结构、字体、颜色、控件语法四层
- 只能以 `/Users/jianglong/workspace/XClaw` 作为唯一真实工作树

## 三轮复盘结论

### 第一轮

旧主线“深红铜 + 石墨黑 / 瓷白灰”只定义了品牌方向，没有定义桌面基底，因此实现很容易退回网页视觉。

### 第二轮

真正决定去网页感的不是主色，而是 `source list / titlebar / sidebar / search / input` 这些壳层语法。

### 第三轮

最终结论确认：

> 去网页感的正确路径不是“做自己的漂亮主题”，而是“先对齐 `QClaw` 的桌面基底，再让 `XClaw` 品牌以点缀形式出现”。

## 验收标准

- 肉眼观察下，不再出现“暖色网页 + 渐变卡片 + 厚表单”的旧气质
- 侧栏、聊天列表、输入区、标题栏都更像桌面应用，而不是网页面板
- 字体统一回系统无衬线栈
- 品牌色退回点缀层，不再充当大面积底色
- 深浅主题都保持工业级桌面质感
- 在不复制 `QClaw` 像素皮的前提下，整体壳层逻辑与它处于同一桌面语言体系
