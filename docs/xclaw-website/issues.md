# XClaw 官网问题记录

## 1. 不能把三个参考站直接拼接

用户明确提出参考 `oneclaw`、`qclaw`、`openclaw` 三个站，但如果直接拼接它们的术语和视觉，会导致：

- 官网失去 `XClaw` 自己的产品边界
- 页面术语混乱
- 视觉像竞品集合页，而不是自有官网

处理：

- 只吸收三者各自有效的方法
- 不直接照搬文案与品牌叙事

## 2. 不能把官网写成技术说明书

目标用户不是已经理解底层架构的开发者，而是想用 AI、但不想碰终端和配置文件的人。

处理：

- 统一使用用户结果词、场景词和产品词
- 禁止内部实现词占据主文案

## 3. 主文案不提底层技术来源

用户明确提出：

- 首页和主叙事不提 `OpenClaw`
- 参考站里也没有直接把底层技术来源放在主卖点里

处理：

- 本轮官网主文案不提底层技术来源
- 如后续确实需要说明兼容或来源，只允许放在页脚或 FAQ

## 4. 官网不应并入桌面应用主路由

如果直接把官网塞进 `src/App.tsx` 当前主路由，会带来：

- Electron 应用壳层和官网职责混杂
- `setup` 与工作台状态逻辑污染官网
- 后续部署困难

处理：

- 做成仓库内独立本地官网产物

## 5. 当前最强证据是产品截图，不是品牌大片

仓库当前已有的最强证据是：

- README 截图
- 现有 logo 和字标
- 真实渠道与模型图标

而不是：

- 大量高质量 3D 品牌插画
- 一整套官网摄影或品牌海报素材

处理：

- 视觉以冷黑工业版承载真实截图
- 不走重品牌大片路线
