# XClaw 官网问题记录

## 1. 不能把三个参考站直接拼接

用户明确提出参考 `oneclaw`、`qclaw`、`openclaw` 三个站，但如果直接拼接它们的术语和视觉，会导致：

- 官网失去 `XClaw` 自己的产品边界
- 页面术语混乱
- 视觉像竞品集合页，而不是自有官网

处理：

- 只吸收三者各自有效的方法
- 不直接照搬文案与品牌叙事

## 2. 不能把官网写成技术说明书

目标用户不是已经理解底层架构的开发者，而是想用 AI、但不想碰终端和配置文件的人。

处理：

- 统一使用用户结果词、场景词和产品词
- 禁止内部实现词占据主文案

## 3. 主文案不提底层技术来源

用户明确提出：

- 首页和主叙事不提 `OpenClaw`
- 参考站里也没有直接把底层技术来源放在主卖点里

处理：

- 本轮官网主文案不提底层技术来源
- 如后续确实需要说明兼容或来源，只允许放在页脚或 FAQ

## 4. 官网不应并入桌面应用主路由

如果直接把官网塞进 `src/App.tsx` 当前主路由，会带来：

- Electron 应用壳层和官网职责混杂
- `setup` 与工作台状态逻辑污染官网
- 后续部署困难

处理：

- 做成仓库内独立本地官网产物

## 5. 当前最强证据是产品截图，不是品牌大片

仓库当前已有的最强证据是：

- README 截图
- 现有 logo 和字标
- 真实渠道与模型图标

而不是：

- 大量高质量 3D 品牌插画
- 一整套官网摄影或品牌海报素材

处理：

- 视觉以冷黑工业版承载真实截图
- 不走重品牌大片路线

## 6. 下载按钮当前仍统一落到 Releases 页面

当前官网下载区已经具备系统分栏和清晰按钮，但为了先完成本地可预览版本，本轮所有下载按钮都统一指向：

- `https://github.com/jlon/XClaw/releases`

这意味着：

- 页面转化路径已经成立
- 但还没有做到按系统直达具体产物

处理：

- 本轮先保留统一 Releases 入口
- 后续如果要正式上线，再补 `macOS / Windows / Linux` 的精确下载链接

## 7. 用户反馈首版页面“太丑、文字太多”

首版虽然已经完成独立官网能力和真实素材接入，但页面仍然更像产品介绍页，和用户参考的 `oneclaw / qclaw` 首页相比存在两个明显偏差：

- 首屏转化不够集中
- 区块解释过多，发布页节奏不够干脆

处理：

- 不做像素级照搬，避免品牌和版权风险
- 直接吸收参考站的版式节奏，收缩为更短的首页骨架
- 将页面主结构压缩为 `Hero -> 功能卡片 -> 三步上手 -> 界面预览 -> 下载 -> FAQ`
- 继续保留 `XClaw` 自有品牌素材与真实截图

## 8. 用户要求学习 `oneclaw` 动效，但不能直接复刻

如果直接复制 `oneclaw` 现有的淡入、切换和微交互节奏，会有两个问题：

- 首页会进一步像参考站翻版
- 动效语言和 `XClaw` 当前更硬朗的黑色视觉不完全匹配

处理：

- 只借鉴“轻、快、能提气质”的节奏，不照搬动画形式
- 首屏采用漂浮、光晕和顺序入场
- 中段采用滚动显现
- 截图切换采用侧滑与扫光组合
- 同时保留 `prefers-reduced-motion` 兜底

## 9. 用户希望学习 `youclaw` 的完整产品站结构

用户这一步的真实诉求已经不是继续微调下载页，而是把首页升级成更接近完整产品官网的结构，包括：

- 更完整的产品站信息层级
- 更强的 Hero 承接
- 场景区、能力区和下载收口的完整闭环

但不能直接照搬 `youclaw`，原因同样明确：

- 品牌、文案和业务模块不属于 `XClaw`
- `youclaw` 还包含 `Pricing / Login / Invite Code / Community` 等当前并不具备的叙事

处理：

- 只吸收其信息架构、视觉节奏和产品站密度
- 保留 `XClaw` 的中文术语、本地截图和 GitHub Releases 下载路径
- 将首页重排为 `Hero -> 真实界面 -> 使用场景 -> 核心能力 -> 两步上手 -> 下载收口 -> 页脚`

## 10. 第一轮 `youclaw` 化改造仍不够精致

在第一轮结构重排之后，页面虽然已经接近完整产品站，但和参考站相比仍有明显视觉落差：

- 首屏字标依赖位图遮罩，观感发糊
- 标题、卡片和区块之间的重量分配偏重
- 卡片边框和材质还不够轻，容易显得发闷

处理：

- 改用更清晰的品牌字标排版，不再依赖模糊遮罩
- 重新调整 Hero 的比例、留白、光晕、轨道和按钮重量
- 为场景卡和能力卡补充分色材质，但保持整体仍服务于黑色主视觉

## 11. 下载按钮需要吸收 `qclaw` 的系统分发感

第二轮精修之后，页面整体已经更接近 `youclaw`，但下载区仍然保留了较重的“两行卡片式”写法，和用户明确指出的 `qclaw` 下载按钮语言不一致：

- 信息密度偏高
- 视觉更像产品卡片，不像系统下载入口
- 和首屏转化动作的直接性不够匹配

处理：

- 将下载按钮改为单行系统名称
- 左侧补充系统图标
- 按 `3 : 3 : 2` 的宽度关系重排三个按钮
- 保留黑色官网主体，不照搬 `qclaw` 整页的扁平风格

## 12. Hero 主体曾经下坠，导航下方留白过多

在吸收 `qclaw` 下载按钮之后，首屏主体与导航之间仍有一段过空的区域，用户明确指出这会让 Hero 看起来像“掉下去一截”。

处理：

- 整体上提 badge、logo、标题和下载区
- 同步上提光晕、轨道和装饰点，避免背景与主体错位
- 保持 Hero 的黑色氛围和空间感，但不再牺牲首屏重心

进一步检查后确认，问题不只来自内容位置偏低，还来自 Hero 被错误纳入了统一的区块顶部间距规则。

补充处理：

- 将 Hero 从通用区块 `margin-top` 规则中移出
- 保留后续区块之间的统一节奏，但首屏不再平白多出一段顶部空白

## 13. 官网截图在构建产物里出现空框

用户补充新截图后，页面表面上已经新增了 tab，但浏览器实际显示为空框。问题不在图片本身，而在截图路径的组织方式：

- 旧写法依赖运行时路径拼接
- 在构建产物里不会被稳定打包
- 结果是页面能拿到标签名，却拿不到真正的图片资源

处理：

- 改为按文件名从 `resources/screenshot/zh` 里静态收集图片
- 让截图资源随 `dist/website` 一起构建
- 同时把 `agents / models / settings` 等新增截图并入官网预览区

## 14. 预览框与真实截图出现双顶栏重复

在截图资源修好后，用户继续指出预览区顶部出现重复窗口头。问题来自两层来源叠加：

- 官网预览框自己画了一层假窗口顶栏
- 新截图本身已经包含真实系统窗口头

处理：

- 删除官网预览框里的假顶栏
- 只保留真实截图自带的窗口头，避免视觉重复

## 15. Hero 中文标题被压成过长字墙

用户继续指出首屏标题“太长”，这个判断是对的。问题不在文案本身，而在排版策略错误：

- 标题容器过窄
- 字号和字重偏重
- 结果是中文标题被硬拆成 4 行，视觉上显得笨重

处理：

- 放宽标题宽度
- 略降字号和字重
- 启用更平衡的换行策略，让标题稳定落在 2 到 3 行

## 16. 首屏整体仍像“AI 海报”，不够像真实产品发布页

用户继续指出页面虽然已经更接近参考站，但精致感、高清感和产品感仍不够，尤其是首屏还保留了比较强的“AI 模板页”特征：

- 左侧堆了过重的大标题和说明块
- 右侧截图没有形成真正的产品舞台
- 中间信息层级更像概念海报，不像能承接下载的发布页

处理：

- 将 Hero 从“字标 + 大标题 + 统计卡”重构为“精简标题 + 系统下载按钮 + 真实截图舞台”
- 用真实产品截图直接承接首屏，不再靠悬空 logo 和装饰元素撑画面
- 把统计卡改成更轻的事实信息条，减少说明书感
- 把展示区改成主画面 + 侧边缩略图，提升产品站的浏览节奏

## 17. 中文标题即使缩短后，浏览器仍可能在单行内部乱断

在首屏重构之后，标题文案已经压短，但如果只依赖浏览器自然换行，中文仍然可能在单行内部被拆开，导致视觉不稳定：

- 设计预期是两行短句
- 浏览器默认会在单行内部继续断开
- 一旦断行失控，Hero 仍会重新变回字墙

处理：

- 继续缩短标题文案
- 放宽 Hero 左侧列宽和标题容器宽度
- 为标题每一行显式加上不换行约束，只保留设计层面的两次换行
