# XClaw 官网设计

## 背景

当前仓库已经具备成熟的桌面应用能力和一批可直接复用的真实素材，包括：

- `README.md` 中的产品截图
- `src/assets/logo.svg`
- `src/assets/xclaw-wordmark-mask.png`
- 渠道与模型相关图标素材

但仓库内还没有一套与 `XClaw` 当前品牌和产品能力一致的官网落地页。  
如果直接复用或拼接 `oneclaw / qclaw / openclaw` 的表达方式，会出现三个问题：

- 术语体系混乱，页面像多个产品的混合物
- 文案边界失真，容易引入不属于 `XClaw` 当前主卖点的叙事
- 官网会更像概念页，而不是一个真实可下载的桌面产品页

本轮设计目标不是“模仿某个站”，而是吸收这三者各自正确的部分，再收敛成 `XClaw` 自己的官网表达。

## 目标

- 为 `XClaw` 新增一套本地可预览的单页官网
- 页面主色调以黑色为主，形成稳定、克制、偏工业化的桌面产品气质
- 官网核心目标是推动下载，而不是介绍底层架构
- 文案面向“想用 AI，但不想碰终端和配置文件的人”
- 网站内容必须尽量建立在仓库中已有真实能力和真实素材上
- 产物先放在本地，便于直接预览和调整

## 非目标

- 不在本轮做多页面官网
- 不在主文案中展开底层技术来源和架构细节
- 不把官网直接塞进现有 Electron 工作台路由
- 不引入大量外部依赖、在线图片或临时素材
- 不把官网做成发布会风格的品牌大片页

## 用户与转化目标

### 目标用户

本轮官网的目标用户明确为：

> 想用 AI，但不想碰终端和配置文件的人

这意味着官网不能写成开发者工具说明书，也不能假设用户理解 `runtime`、`gateway`、`plugin`、`orchestration` 等内部实现词。

### 首页第一目标

首页第一目标固定为：

> 让用户尽快理解 `XClaw` 是一个可以直接下载和使用的桌面工作台

因此页面结构和文案都要优先服务于下载转化。

## 术语体系

### 主术语

官网主文案统一使用以下术语：

- `桌面工作台`
- `多渠道接入`
- `技能扩展`
- `定时任务`
- `模型管理`
- `本地可控`

这些词都直接对应当前产品的真实页面和真实能力，既能让用户理解，又不会落入纯技术实现词。

### 辅助术语

在首屏痛点句、按钮、副标题等位置，可以少量使用以下直白表达：

- `不用终端`
- `不碰配置文件`
- `一个界面完成`
- `打开就能上手`

这些词只做辅助，不取代主术语体系。

### 禁用术语

以下表达不作为官网主文案使用：

- `runtime`
- `gateway`
- `plugin`
- `orchestration`
- `host api`
- 过于泛化的 `AI 助手`

如果后续确实需要说明技术来源，应下沉到页脚或 FAQ，而不能占据首屏或核心能力区。

## 信息架构

官网固定为单页结构，顺序如下：

1. 首屏 Hero
2. 为什么用 XClaw
3. 看看界面
4. 核心能力
5. 常用场景
6. 使用方式
7. 下载与安装
8. 常见问题
9. 结尾下载区与页脚

### 1. 首屏 Hero

职责：

- 在第一屏说清楚产品结果，而不是技术原理
- 直接出现下载按钮
- 通过桌面感强的主视觉和真实产品截图建立可信度

建议文案方向：

- 眉标：`桌面工作台 / 多渠道接入 / 本地可控`
- 主标题：`把复杂 AI 能力收进一个桌面工作台`
- 副标题：`不用终端，不碰配置文件，在一个桌面应用里完成对话、渠道接入、技能扩展、定时任务和模型管理。`
- 主按钮：`立即下载`
- 次按钮：`看看界面`

### 2. 为什么用 XClaw

职责：

- 把“为什么值得下载”说清楚
- 从用户感知角度讲变化，而不是讲系统设计

建议内容：

- `不用终端`
- `一个界面完成`
- `本地可控`

### 3. 看看界面

职责：

- 直接展示 `README` 中已有真实截图
- 通过真实页面而不是概念图证明产品可信度

展示方式：

- 左侧或顶部做页面标签切换
- 右侧展示对应截图
- 标签建议使用：
  - `对话工作台`
  - `多渠道接入`
  - `技能扩展`
  - `定时任务`
  - `模型管理`
  - `设置`

### 4. 核心能力

职责：

- 用产品词解释模块能力
- 每张卡片说“它解决什么”，不说“它怎么实现”

固定卡片：

- `对话工作台`
- `多渠道接入`
- `技能扩展`
- `定时任务`
- `模型管理`
- `本地可控`

### 5. 常用场景

职责：

- 吸收 `qclaw` 的场景表达方式
- 用具体结果而不是抽象概念说服用户

建议场景：

- `整理文件和资料`
- `管理多渠道消息`
- `按时间自动执行`
- `在一个界面里切换模型与能力`

### 6. 使用方式

职责：

- 给用户一个非常轻的上手路径
- 吸收 `oneclaw / qclaw` 的“三步上手”结构，但改写为 `XClaw` 的桌面流程

建议步骤：

1. `下载安装`
2. `完成基础设置`
3. `开始使用`

### 7. 下载与安装

职责：

- 让用户在页面中后段再次获得明确下载入口
- 不把下载信息埋在页脚

建议内容：

- `macOS`
- `Windows`
- `Linux`

说明：

- `macOS` 需要区分 `Apple Silicon` 与 `Intel`
- `Windows` 直接给下载按钮
- `Linux` 允许先以轻量说明承接，不强行做复杂下载矩阵

### 8. 常见问题

职责：

- 只回答下载前最常见的问题
- 不把页面拖进冗长的文档化说明

建议问题：

- `适合什么样的用户？`
- `支持哪些系统？`
- `下载安装后需要准备什么？`
- `需要写命令或改配置文件吗？`

## 视觉方向

### 最终方向

本轮视觉方向固定为：

> `A / 冷黑工业版`

这是三轮对比后确认的结果。

### 视觉原则

- 以冷黑色为主基底，避免发紫、发蓝的常见 AI SaaS 配色
- 用少量铜橙色做按钮、焦点和局部强调
- 用更接近桌面产品的边框、层级和窗口轮廓建立可信度
- 优先突出真实产品截图，而不是大面积抽象背景或品牌海报
- 页面氛围要克制、稳定、偏工业化，而不是漂浮、空灵或发布会化

### 不采用的方向

- 不采用强宇宙感、深空感的“概念产品”方向
- 不采用高对比品牌大片式布局作为主方向
- 不使用大面积炫光、霓虹、玻璃拟态或泛滥的渐变球

## 参考吸收策略

### 来自 oneclaw 的有效部分

- 转化路径直接
- 标题和副标题面向普通用户
- 下载入口清晰
- “快速上手 / 看看效果” 这类导航足够直白

### 来自 qclaw 的有效部分

- 更像真实产品而不是概念页
- 能力表达更偏场景和结果
- “三步上手” 和 “真实场景” 的组织方式清晰

### 来自 openclaw 的有效部分

- 能力拆分简洁明确
- 页面整体气质克制，不是乱堆卖点
- 模块命名短、准、可扫读

### 本轮不直接照搬的部分

- 不直接沿用三者的术语原文
- 不把它们的品牌叙事搬到 `XClaw`
- 不在首页主文案里直接重复它们的技术主张

## 落地方式

### 技术策略

官网不进入现有 Electron 应用的主路由，不修改当前桌面产品入口逻辑。

原因：

- 现有应用包含 `setup` 与工作台路由，不适合直接兼做营销官网
- 继续复用 Electron 路由会引入不必要的壳层样式与状态逻辑
- 官网和桌面应用职责不同，应该分离入口

因此本轮采用：

> 在仓库内新增一个独立的本地官网产物

该产物：

- 与桌面应用共用品牌素材
- 但不共用产品运行入口
- 可以单独本地预览
- 后续可独立部署

### 素材复用原则

优先使用以下本地素材：

- `resources/screenshot/en/*.png`
- `resources/screenshot/zh/*.png`
- `src/assets/logo.svg`
- `src/assets/xclaw-wordmark-mask.png`
- `src/assets/channels/*`
- `src/assets/providers/*`

禁止：

- 依赖外站图片
- 引入与产品无关的生成式插画
- 用无法在仓库中追溯来源的临时素材

## 风险与控制

## 1. 术语漂移风险

如果实现时重新混入开发者语言，官网会失去当前已经确认好的用户表达。

控制：

- 所有主标题、区块标题、按钮文案都按本设计文档执行

## 2. 视觉过度营销风险

如果过度强调氛围和品牌大片感，会冲淡 `XClaw` 作为真实桌面产品的可信度。

控制：

- 保持真实截图为核心证据
- 背景和动效只做辅助

## 3. 与桌面主应用耦合风险

如果官网直接并入现有桌面入口，会引入路由、样式和状态上的额外复杂度。

控制：

- 独立入口
- 独立页面壳层
- 只复用必要的静态素材

## 验收标准

- 本地可以直接预览官网
- 桌面端和移动端都能正常排版
- 所有主要图片均来自本地仓库
- 页面结构与本设计文档一致
- 官网主文案遵循本轮确认的术语体系
- 页面主视觉符合冷黑工业版方向

## 当前结论

本轮官网设计已经确认以下事实：

- 范围：`单页官网`
- 目标：`推动下载`
- 用户：`想用 AI，但不想碰终端和配置文件的人`
- 语气：`克制专业`
- 术语：`A 为主，B 为辅`
- 视觉：`A / 冷黑工业版`
- 落地：`仓库内独立本地官网产物`

后续实现必须严格以这些已确认结论为准，不再回退到“先模仿别人的站”或“直接换同义词”的路径。
