# 全局壁纸设计

## 用户目标

- 提供类似 iTerm / Tabby / Temux 的整窗壁纸能力
- 用户可上传一张本地图片，作为主应用壳层的统一背景
- 用户可调节壁纸透出强度，但不需要首版暴露过多高级参数

## 范围

- 覆盖主应用壳层：
  - 聊天
  - 模型
  - 智能体
  - 频道
  - 技能
  - 定时任务
  - 设置
  - 工作台 / Studio
- 壁纸铺设在整窗壳层后面，而不是某个页面卡片内部
- 左侧栏、标题栏、主工作区都要切到可透出壁纸的半透明材质
- 设置入口放在 `Settings > Appearance`

## 非目标

- 不覆盖 setup 引导页
- 不支持每个页面单独设置壁纸
- 不支持多张轮播
- 不支持视频背景
- 不支持铺放模式、模糊强度、遮罩颜色等高级参数

## 交互设计

### 设置项

- 壁纸开关
- 上传图片
- 清除图片
- 透明度滑杆

### 首版交互规则

- 用户上传图片后，立即显示预览态并应用到主壳层
- 用户关闭壁纸时，不删除已导入图片，只停用当前配置
- 用户点击清除时，清空当前壁纸配置并删除受控文件
- 透明度滑杆只控制壁纸层可见度，不直接暴露前景面板透明度

## 数据与持久化

### 设置字段

建议新增：

- `globalWallpaperEnabled: boolean`
- `globalWallpaperOpacity: number`
- `globalWallpaperAssetPath: string`

### 文件托管

- 不直接依赖用户原始选择路径
- 选图后复制到 `app.getPath('userData')/wallpaper/`
- 主进程负责生成稳定文件名，并在替换时清理旧文件

### 读取原则

- Renderer 只消费受控路径
- 如果文件丢失、不可读或已损坏，自动回退为无壁纸

## 架构设计

### 主进程

- 提供壁纸导入与清除能力
- 负责把用户选择的图片复制到 `userData/wallpaper/`
- 写入 settings 中的受控壁纸路径与状态

### Renderer

- `Settings` 页面负责触发上传、清除与参数修改
- `MainLayout` 根壳层负责渲染统一 wallpaper layer
- 现有 sidebar / titlebar / workspace surface 在壁纸开启时切到半透明材质

## 渲染规则

### 壁纸层

- 挂在 `desktop-app-shell` 根层
- 使用 `background-image` 覆盖整个主应用窗口
- 使用 `background-size: cover`
- 使用统一遮罩层保证文本可读性

### 壳层联动

- 标题栏、侧栏、主工作区容器在壁纸模式下不再使用完全不透明背景
- 保持现有圆角、分隔线和层级关系不变
- 不在页面子组件内部重复铺设背景图

### 聊天页特例

- 聊天页不能直接复用工作台卡片页的 pane glass，否则暖色或高饱和壁纸会直接污染正文阅读层
- 聊天页需要单独的 `reading plane`：
  - 底部仍是整窗壁纸与统一 shell material
  - 消息滚动区增加一层中性阅读底板，负责切断壁纸色温
  - 输入框保留玻璃感，但密度高于工作台卡片，避免与消息层糊成一片
- 聊天侧栏头部采用单层结构：
  - macOS 下 titlebar 左槽位只承载会话控制，品牌与搜索保留在 pane 顶部
  - 品牌与会话列表保持同一侧栏内容节奏，不能被抬到 traffic lights 所在的标题栏行
  - 焦点模式下仅保留标题栏中的会话显隐控制，不保留重复的新建入口
- 助手消息采用“文档流”表达，不再使用大面积半透明整块气泡
- 用户消息保留轻量气泡，用于维持说话者区分，但其底色也要跟随聊天专属 token 收敛，不能回退成工作台白卡

## 失败回退

- 选图失败：保持原状态，不写入 settings
- 文件复制失败：提示失败，不进入半配置状态
- 壁纸文件缺失：自动关闭壁纸并回退默认壳层
- 非图片文件或不可解码文件：拒绝导入

## 首版取舍

- 只做“整窗统一壁纸 + 一个透明度滑杆”
- 首版优先保证可读性、自洽和稳定，而不是参数自由度
