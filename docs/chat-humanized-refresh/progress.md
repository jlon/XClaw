# 聊天区域人性化设计优化进度

## 当前状态

开发中。

第二阶段聚焦：

1. 聊天消息区的人性化设计。
2. 快捷操作的发现性与克制感平衡。
3. 过程轨语义统一。

## 已完成

1. 已确认第一阶段仍未完全以产品验收口径闭环，但工程结构已经足以承接第二阶段。
2. 已完成 `QClaw` 聊天设计的第二轮对照，确认其真正有价值的部分在于：
   - 正文优先
   - 快捷操作默认弱化
   - 过程轨轻量统一
3. 已明确第二阶段不复制的部分：
   - 像素化视觉皮
   - 重型反馈面板
   - 无本地协议支撑的 hook 交互
4. 已建立本 feature 文档。
5. 第一刀已完成落地：
   - `ChatMessage` 的 meta row 继续收平
   - `thinking / tool` 开始统一成同一套轻过程轨
6. 第二刀已完成落地：
   - 用户消息继续压低热度，只保留轻 tint
   - 助手消息保留文稿流，不回退成厚卡片
   - 附件、图片、代码块进一步收平
7. 第三刀已完成落地：
   - `@`、模型、回到底部等快捷操作默认继续弱化
   - 激活态才增强，不再默认抢正文
8. 已完成定向验证：
   - `chat-message + chat-theme-shell` 通过
   - `chat-input + chat-theme-shell` 通过
9. 已拿到本机解包 `QClaw` 的第二阶段直接证据：
   - 用户消息更像被盖章的输入
   - 助手消息更像铺在画布上的结果
   - 次级动作默认接近隐身，hover 才抬起
10. 已基于该证据继续收了一刀：
   - 消息下方 meta row 默认继续弱化
   - 复制/时间只在 hover 或 focus-within 时完整抬起
11. 已继续收正文里的块级元素：
   - 代码块去掉品牌强调边
   - 附件卡和图片卡进一步去网页卡片感
   - tool 展开行去掉多余装饰图标
12. 相关最小验证已通过：
   - `chat-message + chat-theme-shell` 定向回归继续通过
13. 已继续收连续 assistant 输出的身份层：
   - 连续 assistant 消息不再重复抬起头像
   - typing / tool processing 会复用同一条身份轨道
   - streaming 行没有真实时间戳时不再伪造时间
   - 连续 assistant 行之间的垂直节奏收紧，不再和异角色切换保持同样的大间距
14. 已继续收长会话里的垂直阅读节奏：
   - 连续 assistant 输出之间改成紧凑间距
   - 角色切换时才恢复标准段落间距
   - 不再把所有消息一律拉成同一个 `space-y`
15. 已继续收空态与次级信息密度：
   - 欢迎态从 landing hero 进一步压回启动工作区
   - meta row 默认继续弱化，但 hover/focus 仍能抬起
   - 过程轨节点、行距、图标和文案整体再降一档热度
16. 已继续收正文里的块级存在感：
   - 代码块圆角、边界和背景继续收平
   - 附件卡和图片卡继续弱化卡片轮廓
   - 正文、附件、图片和代码块的主次关系更稳定
17. 已继续向 `QClaw` 的默认段距节奏靠拢：
   - 连续 assistant 输出的段距进一步压到更接近 `8px`
   - 角色切换仍保留更清楚的阅读呼吸感
   - 这次只收段距，不改消息协议和分组语义

## 当前实施清单

1. 继续基于现有 `ChatMessage / ChatInput / Chat index` 收口改造面。
2. 保持消息动作层、过程轨、主视觉层级这三条线一致。
3. 用最小测试锁住“默认弱化、激活增强”的快捷操作语义。
4. 继续核对 `QClaw` 的真实证据，只吸收有本地问题支撑的部分。
5. 继续减少长会话里的重复身份 chrome，但不引入协议级分组。
6. 继续检查连续 assistant 段落的间距是否还需要再压一档，但不牺牲可读性。
