# 聊天区域人性化设计优化进度

## 当前状态

开发中。

第二阶段聚焦：

1. 聊天消息区的人性化设计。
2. 快捷操作的发现性与克制感平衡。
3. 过程轨语义统一。
4. 在不破坏壁纸功能的前提下，把聊天主区、侧栏和 composer 的明暗关系收成更接近 `QClaw` 的桌面阅读区。

## 当前实施清单

1. 继续基于现有 `ChatMessage / ChatInput / Chat index` 收口改造面。
2. 保持消息动作层、过程轨、主视觉层级这三条线一致。
3. 用最小测试锁住“默认弱化、激活增强”的快捷操作语义。
4. 继续核对 `QClaw` 的真实证据，只吸收有本地问题支撑的部分。
5. 继续减少长会话里的重复身份 chrome，但不引入协议级分组。
6. 继续检查连续 assistant 段落的间距是否还需要再压一档，但不牺牲可读性。
7. 主区、侧栏、composer 的层级调整继续限制在聊天局部，不回头改全局壁纸导入链路。
8. 聊天路由的明暗关系改为结构性分层，不再继续依赖 `opacity + 0.02` 这类肉眼不可感知的微调。
9. 聊天主区颜色继续保持中性白优先，不把品牌暖色直接铺进阅读面。
10. 聊天路由的 `wallpaper-on` 与 `wallpaper-off` 必须是两套透明度策略，不能混成一套常量白面。
