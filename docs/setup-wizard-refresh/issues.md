# Setup 引导页重构问题跟踪

## 当前问题

### 1. `Setup` 页面主文件仍然偏大

虽然四阶段骨架、阶段组件和主 CTA 契约已经拆开，但 `src/pages/Setup/index.tsx` 仍然承载了较多状态编排和 provider 交互逻辑，后续继续演进时仍有维护压力。

### 2. Win/mac 真机手工 smoke 还未完成

当前已经有代码级、页面级和构建级验证，但桌面向导最终仍需要在真实窗口环境里确认：

- 默认窗口宽度下的可读性
- mac 的轻量壳层观感
- Windows 的边界和滚动区表现

### 3. 完成页的首次推荐动作仍可继续增强

当前完成页已经能正确表达 provider、组件和 gateway 摘要，但是否补一个更明确的“下一站推荐入口”，仍可以在后续小版本继续优化。

## 设计阶段决议

- 固定四阶段骨架：`开始 / 准备 / 模型与接入 / 完成`
- 改成“左侧步骤导航 + 右侧内容区 + 底部固定操作栏”
- `takeover provider review` 不再维持独立主步骤，合并进固定骨架
- 日志和高级诊断进入折叠次级路径

## 未决问题

### 1. Setup 是否继续复用主窗口默认尺寸

如果仍走当前主窗口尺寸，需要确认四阶段壳层在默认宽度下是否足够舒展。

### 2. 完成页是否展示更多首次推荐动作

例如是否在完成页提供“进入频道中心”或“去设置补充高级项”的推荐入口。

### 3. OAuth 手动 code 兜底是否还要继续保留在主流程

当前倾向保留，但降低优先级，放入次级区。
