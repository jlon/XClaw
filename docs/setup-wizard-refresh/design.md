# Setup 引导页重构设计

## 定位

`setup-wizard-refresh` 只负责 **引导页的产品体验与桌面版式合同**，不负责 takeover 事务、回滚、Gateway 并发、漂移回收这类运行时设计。

这些运行时问题继续留在 [setup-openclaw-takeover](/Users/jianglong/workspace/XClaw/docs/setup-openclaw-takeover/design.md)。

如果继续把两者混在一起，页面就会自然退化成“工程后台 + 流程卡片”，而不是桌面级引导。

## 当前问题

当前 `Setup` 的问题不是颜色，而是信息架构：

- 默认桌面宽度下，步骤轨没有稳定成为左侧进度轨
- 当前步骤面同时承载欢迎说明、路径选择、环境摘要、冲突、运行状态，违反单任务原则
- 页面大量使用等权重卡片，导致“当前动作”不清楚
- takeover 的技术事实过多上屏，把引导页做成了运维面板
- footer 虽然存在，但当前步骤并没有真正围绕 footer 的单主动作组织

## 目标

- 把 `Setup` 收成 **左侧进度轨 + 右侧单任务工作面 + 底部固定动作栏**
- `fresh / takeover` 共用同一套向导骨架，不再长出两种产品形态
- 每一步只解决一个主要问题
- 默认桌面窗口下不依赖内部滚动条来修布局
- 引导页保持桌面级质感，但不做成营销落地页

## 非目标

- 不在本轮重写 takeover 事务逻辑
- 不在本轮重做 provider/runtime 业务规则
- 不把引导页做成设置页或后台控制台
- 不引入复杂动画、插画轮播或大面积营销文案

## 引导页铁律

### SW-01 左轨只负责进度

- 左侧只展示阶段顺序、当前步骤、完成状态
- 左轨不承载正文说明
- 左轨默认不可点击跳步
- 默认桌面窗口下左轨必须稳定可见

### SW-02 右侧只承载当前一步

- 右侧只能有一个当前任务面
- 同一步里的次级事实进入折叠区、摘要区或底部说明
- 不允许“欢迎说明 + 配置表单 + 诊断日志 + 风险提示”同时堆满首屏

### SW-03 底部只有一个主 CTA

- 每一步只能有一个主动作
- `继续 / 开始接管 / 保存并继续 / 进入 XClaw` 这些动作只能在 footer 主按钮出现
- 页面内部允许有次级操作，但不能与 footer 主 CTA 竞争

### SW-04 每一步只做一个决策

- `开始`：决定走 takeover 还是 fresh
- `准备`：确认环境是否可继续
- `模型与接入`：决定模型接入方式
- `完成`：确认进入应用

如果某一步需要用户同时做多个主要决策，说明这一步设计失败。

### SW-05 先删重复文字，再做视觉层级

- 不允许标题、说明、摘要卡重复表达同一件事
- 不允许把 takeover 的技术事实写成大段说明
- 清晰度来自边界、节奏、字重和主次关系，不来自大卡片堆叠

### SW-06 引导页允许展示感，但不允许营销页化

- welcome/fresh 起始面可以比工作台更柔和
- 但品牌展示必须服务“开始配置”这件事
- 不能出现工作台首页式的信息密度

### SW-07 默认窗口下不靠内部滚动解法

- 默认桌面尺寸按 `1280x800`、`1440x900` 验收
- 当前步骤的主任务面必须在这个范围内稳定成立
- 只有日志、长诊断、长列表允许进入次级滚动区

## 布局合同

### 整体骨架

- 左：固定宽度进度轨
- 右：当前步骤工作面
- 下：固定动作栏

默认桌面宽度下，右面板是主视觉，左轨退为弱导航。

### 左侧进度轨

- 宽度控制在 `220-260px`
- 顶部只保留轻品牌锚点
- 步骤项是紧凑行，不是大按钮卡
- 只展示：
  - 序号或完成态
  - 标题
- 不展示长描述

### 右侧工作面

- 只保留一个大面板
- 标题区只展示：
  - 当前步骤标题
  - 一句必要说明
- 当前任务控件紧接标题区出现
- 风险、警告、诊断进入次级区

### 底部动作栏

- 左侧：返回或取消
- 右侧：唯一主动作
- applying 状态下不允许跳步

## 四阶段任务定义

### 1. 开始

主任务：选择路径。

允许上屏：

- 标题
- 一句说明
- 两张路径卡
- 选中路径的轻摘要
- 必要的阻塞/警告

不允许上屏：

- provider 表单
- takeover 技术细节长列表
- 日志
- 运行时进度

### 2. 准备

主任务：确认环境就绪。

`fresh`：

- 工作目录
- Gateway 端口
- 环境检查摘要

`takeover`：

- 将导入的主要资产摘要
- 冲突与阻塞

高级项：

- 详细日志
- 重试检查
- 技术诊断

### 3. 模型与接入

主任务：决定模型接入方式。

允许：

- provider 选择
- 必要字段
- 校验状态

不允许：

- 多种接入方式的大面积同时展开
- 长帮助文和字段说明霸占首屏

### 4. 完成

主任务：确认结果并进入应用。

允许：

- 应用中进度
- 最终摘要
- 进入应用

不允许：

- 再做配置
- 再做诊断
- 再做次级路径分流

## 与 takeover 文档的边界

以下内容不再写入本设计，也不再驱动页面版式：

- 备份/提交/回滚事务
- runtime freeze check
- Gateway 自愈与托管策略
- provider 导入算法
- 漂移回收同步
- 双平台发布门槛

这些都继续保留在 takeover 文档中。

## 代码落地要求

### 壳层

- `SetupShell` 必须默认进入左右布局，不再只在超大断点才变成左轨
- `SetupStepRail` 改成紧凑被动进度轨
- `SetupFooter` 保持唯一主 CTA

### 阶段内容

- `SetupStartStage` 重写为“路径选择 + 选中摘要”
- `SetupPreparationStage` 重写为“就绪确认面”，把大量 summary 卡和说明下沉
- `SetupProviderStage` 保持业务逻辑，但压成单任务面
- `SetupCompleteStage` 保持完成感，不再额外塞配置

## 验收标准

满足以下条件才算这轮做对：

1. 默认桌面窗口下，步骤轨稳定在左侧
2. 首步不会再出现“顶部大流程 + 中间多层大卡”的后台观感
3. 当前步骤一眼就能看出唯一主任务
4. footer 主 CTA 始终是唯一主动作
5. `fresh / takeover` 两条路径共用同一套桌面向导骨架
6. 页面内部不再依赖大面积重复说明文字建立秩序
