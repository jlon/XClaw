# 渠道插件内置化问题跟踪

## 当前已知问题

### 1. 飞书旧目录存在历史兼容负担

此前代码同时兼容：

- `openclaw-lark`
- `feishu-openclaw-plugin`

本轮会把旧目录降级为迁移遗留，但仍需保留配置清洗层的一次性兼容。

### 2. 上游飞书包命令描述不稳定

用户给出的 `npx -y @larksuite/openclaw-lark install` 在本机实跑失败，因此本轮实现不会依赖该命令，而是直接使用稳定的 npm 包镜像来源。

### 3. 安装包体积会小幅增加

WeCom 来源切换后，打包内容与依赖结构会变化，最终安装包大小需要在本轮实现后重新评估。

## 后续观察项

- Windows NSIS 产物是否需要单独做一轮实机安装验证
- Feishu 重复插件 id 告警是否在清理旧目录后完全消失
- 当前已验证 mac 本地打包链；Windows 仍缺少实机打包证据
