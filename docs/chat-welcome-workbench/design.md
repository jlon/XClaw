# 聊天欢迎态桌面工作台设计

## 背景

聊天页欢迎态已经完成过一轮主题收口，但用户继续指出两个核心问题：

1. 欢迎区仍然更像网页空态，不像真正的桌面工作台。
2. 三个入口虽然已经横向排列，但内容模型仍然接近“建议卡”，不够像 OpenClaw 的工作模式面板。

用户明确要求参考本机解包后的 `QClaw` 欢迎页，但不能照抄它的场景文案和功能广告位。最终目标是吸收它的模块密度、留白节奏和轻插画卡片气质，再结合 OpenClaw 的真实能力，做出属于 XClaw 自己的聊天起始页。

## 参考结论

### 可以吸收的部分

1. 卡片结构足够轻，只保留标题、说明和底部插画，不堆叠复杂装饰。
2. 卡片像桌面应用里的模块面板，而不是网页营销区。
3. 插画贴底，文字留在上半区，阅读路径直接。
4. 整体是浅色桌面壳层中的局部模块，不是单独 landing page。

### 明确不采用的部分

1. 不照搬 `QClaw` 的五张生活场景卡。
2. 不把聊天欢迎态做成功能展厅。
3. 不复制它的文案语气和图标主题。
4. 不引入与 `global-theme-refresh` 冲突的新页面级主题。

## OpenClaw 特征抽象

这次欢迎态的内容模型必须来自 OpenClaw 的运行方式，而不是来自参考站点的业务场景。结合仓库文档与现有能力，本页重点体现三件事：

1. XClaw 是当前工作区里的执行入口，不是一次性问答框。
2. XClaw 能沿着同一会话、模型和上下文持续推进。
3. XClaw 可以把工作拆给多个 Agent，并继续延伸到频道和定时任务。

## 设计目标

1. 欢迎态一进入就像桌面工作台起始页，而不是 AI landing。
2. 中轴主视觉继续保留，但信息密度向桌面模块靠拢。
3. 欢迎入口改为真正的“工作模式卡”，不再像提示建议。
4. 点击卡片后仍然沿用现有 prompt 注入链路。
5. 文案要去营销腔，避免“AI 助手首页”既视感。

## 非目标

1. 不重做消息列表与输入区主结构。
2. 不新增功能导航、运营 banner 或更多入口。
3. 不建设完整插画系统，只在欢迎态内提供局部抽象插画。
4. 不改动聊天页以外的页面主题语言。

## 最终方案

### 整体结构

欢迎态保留中轴布局，但收成更像桌面工作台首页的四层结构：

1. 小龙虾图标容器
2. 品牌标题
3. 一句功能型副标题
4. 四张横向工作模式卡

顶部不再出现 `Main Agent`，运行异常提示继续保持为轻量状态条，不抢主视觉。
同时整体首屏高度继续向 `QClaw` 靠拢：主视觉、标题和副标题的垂直节奏保持紧凑，避免欢迎区占掉过多聊天工作区高度。
品牌区不再保留额外说明文，避免主标题下出现第二段干瘪补充句。
品牌标题继续服从全局字体体系，但字形来源必须回到 `QClaw` 真源码里的系统 sans 栈，而不是继续伪造 `SF Pro Display` 式展示字栈。
同时已确认 `QClaw` 欢迎头本体是 `logo` 图片加一行副标题，不存在可直接复用的文字标题字体文件，因此这里只能对齐全局字栈、字重与字距语义，不能把品牌图误当字体来追。
因此欢迎头最终不再使用普通文本标题，而是切换为单独的 `XClaw` 字标组件；页面里只保留隐藏 `h1` 负责语义和可访问性。
字标组件也不能继续沿用早期那套粗糙的手写 `SVG` 骨架，而要改成品牌资产逻辑：`Claw` 部分直接以 `QClaw` 欢迎头参考图中的真实几何为基底，`X` 单独按同一重量和圆角语义重做，最后输出为可跟随主题色的 `mask` 资产。

### 主视觉

1. 主视觉不再使用“风格接近”的龙虾图标，而是按 2026-03-21 当天线上 [openclaw.ai](https://openclaw.ai/) Hero 资产结构还原。
2. 还原范围包含三层：小龙虾 SVG、本地局部星点层、局部星云层，而不是只还原中间图标。
3. 小龙虾 SVG 保持线上资产的核心组成：左右钳、触角、眼睛与眼内青色发光点、红色渐变主体。
4. 容器尺寸与动效参数向线上值对齐，保留局部暗底舞台，避免退回成浅色页面里的一枚静态 app icon。
5. 不把线上整屏海报背景直接搬进聊天页，只抽取与主视觉紧密耦合的局部氛围层，保证仍然服从聊天页桌面壳层。
6. 主视觉容器必须是图标级焦点，不能退化成一整块深色横幅。
7. 主视觉底层氛围要跟当前主题背景同源，浅色主题里不能出现独立的黑色舞台块。

### 动效还原范围

本次主视觉不是“做一个会动的类似物”，而是按线上资产的动作语义逐项还原：

1. 整体漂浮：4 秒 `ease-in-out` 无限循环。
2. 眼睛发光点闪动：3 秒 `ease-in-out` 无限循环。
3. 触角摆动：2 秒 `ease-in-out` 无限循环。
4. 左右钳张合：4 秒 `ease-in-out` 无限循环，右钳保留轻微延迟。
5. 默认发光使用红色 `drop-shadow`，hover 切换为更强的青色发光，并停止漂浮，保持与线上交互反馈一致。

### 桌面化增强

在用户确认后，主视觉增加一层桌面应用语境下的低频 special-idle，而不是继续保持网页 Hero 式完全静态复刻：

1. 整体资产保持线上还原版为基础，不改 SVG 结构与已有四类子动作。
2. 额外增加低频伪 3D 待机，每约 17 秒出现一次短时动作。
3. 特殊待机只做轻量 `rotateX / rotateY / rotateZ`、一次小跳和回弹，不做整圈旋转。
4. 地面影子与主体联动，形成轻量景深，强调“桌面工作台里的活体图标”。
5. 这层增强必须低频、短时、不过度抢焦点，不能让欢迎态变成表演型 banner。

### 还原边界

1. 目标是还原线上 Hero 资产本身，不额外加品牌演绎、玻璃拟态或新的容器装饰。
2. 类名、关键帧和结构在本项目中使用 `app-chat-openclaw-*` 前缀隔离，避免污染全局主题。
3. 仍然遵守桌面应用语境，主视觉是工作台起始页焦点，不是网页海报。
4. 伪 3D 仅用 CSS 透视和影子实现，不引入 WebGL 或新资产体系。

### 文案

欢迎区文案切换为带一点亲近感、但仍然像桌面工作台的表达：

1. 标题：`XClaw`
2. 副标题：`小助手已就位，你开口，我开工，给你无限可能`
3. 不再保留额外欢迎说明句
4. 标题继续使用全局标题语义 token，但其实际值与 `QClaw` 真源码里的系统 sans 栈保持一致，不再保留 `SF Pro Display` 预设
5. 视觉层改为独立 `XClaw` 字标，而不是继续把 `XClaw` 作为普通文字直接渲染
6. 字标本体拆出单独组件文件，避免继续内联在聊天页里手工描路径，降低后续维护时再次退回粗糙字形的风险
7. 字标渲染方式改为 `PNG mask + currentColor`，保留桌面主题适配能力，不把欢迎头锁死成单色位图
8. 字标资产边界必须按可见像素紧裁，标题容器宽度使用 `min(100%, clamp(...))` 规则，保证窗口缩放、页面放大和窄宽度下都维持视觉居中

### 四张工作模式卡

工作模式卡从 3 张扩展到 4 张。新增卡片不能是凑数模板，而要补上 OpenClaw 里“能力接入”这一类真实能力面：

1. `当前桌面`
   标题：`直接开工`
   说明：`目标、文件和限制放上来，我先接住，再从这张桌面开始动手。`
2. `同一线程`
   标题：`接着往下`
   说明：`上次做到哪，这次就从哪继续。上下文、模型和线索都留在这条线程里。`
3. `Agent 接力`
   标题：`拆开推进`
   说明：`事情一复杂，就交给不同 Agent 分段接力，让每一部分都继续往前走。`
4. `技能与接入`
   标题：`接上能力`
   说明：`把 Skill、工具和外部接入挂进来，这张桌面就能替你多做几类事。`

### 卡片视觉

卡片视觉融合 `QClaw` 的模块感，但保持 XClaw 自己的语义：

1. 去掉编号和方向箭头，避免看起来像网页建议列表。
2. 卡片结构统一为“类别、标题、说明、底部插画”。
3. 每张卡使用独立浅底色，但都服从统一桌面主题。
4. 桌面宽度下卡片之间保留更接近 `QClaw` 的留白节奏：面板间距放大，品牌区和卡片区之间留出明显呼吸区。
5. 卡片本体进一步精修到更接近桌面模块的高清质感：
   - 圆角统一提升到 `1.15rem`
   - 卡高统一到 `12rem`
   - 底部插画层高度统一到 `6rem`
   - 卡片顶部增加轻量高光层，底部插画保留独立雾化色垫
6. 颜色从原来的 3 色扩展为更接近 `QClaw` 的 4 色面板：
   - `直接开工` 为珊瑚红
   - `接着往下` 为雾蓝
   - `拆开推进` 为琥珀黄
   - `接上能力` 为青绿色
7. 底部插画使用系统隐喻，而不是业务场景插画：
   - `直接开工` 使用托盘、文件和工具片段
   - `接着往下` 使用轨道、面板和节点
   - `拆开推进` 使用路由节点、连接线和能力标签
   - `接上能力` 使用接入口、节点和连接板，不能再和 `直接开工` 的托盘插画撞型

## 验收标准

1. 顶部不再出现 `Main Agent`。
2. 欢迎态在桌面宽度下为 4 张横向模块卡。
3. 四张卡的内容明显来自 OpenClaw 的工作模式与能力接入，而不是 `QClaw` 的场景模板。
4. 中轴主视觉能够还原 OpenClaw 线上小龙虾的结构、局部星点星云氛围和核心动画节奏。
5. hover 主视觉时，发光颜色与动效反馈和线上资产保持同一语义。
6. 主视觉在非 hover 状态下会低频出现一次短暂转身和小跳，但不会演变成持续表演。
7. 欢迎区看起来像桌面工作台入口，不像网页 landing hero。
8. 点击任一卡片后，仍能稳定向输入区注入对应 prompt。
9. 欢迎态继续服从聊天页现有桌面壳层和宽度节奏。
10. 标题下不再出现额外说明句，只保留一行副标题。
11. `接上能力` 的底部插画语义必须明显区别于 `直接开工`，不能看起来像同一套托盘资产换色。
12. 欢迎头字标必须退出旧的粗描边骨架，收成独立组件和 `mask` 品牌资产结构。
