# 聊天欢迎态桌面工作台测试

## 测试目标

确认欢迎态已经从过渡性的“建议卡”切换为真正的桌面工作模式面板，同时确认中轴主视觉已按 OpenClaw 线上资产结构和动画参数落地，且没有破坏原有聊天页壳层契约。

## 自动化覆盖

### 渲染与文案

1. 欢迎态仍然存在 `chat-welcome-hero`。
2. 顶部不再渲染 `Main Agent`。
3. 渲染品牌标题 `XClaw`。
4. 渲染新的副标题，并且不再渲染欢迎说明文。
5. 渲染 4 张新的工作模式卡。
6. `接上能力` 卡仍然存在，但欢迎说明句保持为空，不回退成第二段介绍文。

### 交互

1. 点击 `直接开做` 会向输入区注入执行型 prompt。
2. 点击 `接着往下` 时仍沿用现有 prompt 注入链路。
3. 点击 `拆开推进` 时仍沿用现有 prompt 注入链路。
4. 点击 `接上能力` 时仍沿用现有 prompt 注入链路。

### 源码壳层

1. 欢迎态继续挂在聊天页专用桌面壳层内。
2. 欢迎动作区在桌面宽度下为四列网格。
3. 卡片存在独立变体类名和底部插画容器。
4. 不回退成旧的 `Main Agent` 欢迎标题结构。
5. 主视觉源码包含 `app-chat-openclaw-atmosphere`、`app-chat-openclaw-stars`、`app-chat-openclaw-nebula` 与小龙虾主体结构。
6. 样式源码包含 `float / blink / wiggle / claw-snap` 四类还原关键帧以及红光、青光 hover 过滤器。
7. 样式源码包含 `performance / shadow-drift` 两类桌面化 special-idle 关键帧、透视和影子层。
8. 样式源码不能回退到横幅级深色舞台比例，主视觉必须维持图标级局部氛围层。
9. 浅色主题下主视觉底层必须跟页面背景融合，不能出现独立黑底。
10. 样式源码包含更精细的桌面卡片节奏：`1.18rem` 面板间距、`1.15rem` 圆角、`12rem` 卡高、`6rem` 插画层高度。
11. 欢迎标题继续使用全局标题语义 token，但底层字体值必须和解包后的 `QClaw` 源码一致，不再保留 `SF Pro Display` 式假设。
12. 欢迎头视觉层应改为独立字标组件，页面里只保留隐藏的 `h1` 语义文本。
13. 字标样式源码应升级为 `mask` 品牌资产结构，不能回退到单层粗描边骨架。

## 手工验证清单

1. 在空聊天页打开欢迎态，确认整体像桌面工作区起始页而不是网页横幅。
2. 观察图标容器与小龙虾光晕，确认焦点只停留在局部，不扩散成整页海报。
3. 观察四张卡，确认文字层级是“类别、标题、说明、底部插画”而不是编号建议项。
4. 观察小龙虾主视觉，确认有局部星点、星云、漂浮、眼睛闪动、触角摆动和钳子张合。
5. 等待一个完整周期，确认小龙虾会低频出现一次轻量转身、小跳和回弹，且节奏不突兀。
6. 观察地面影子，确认会跟随 special-idle 收缩和偏移，形成轻量景深。
7. hover 小龙虾，确认由红色发光切到青色发光，并停止漂浮与 special-idle。
8. 在较宽桌面窗口中确认四张卡横向展开，留白均匀。
9. 缩窄窗口，确认卡片会先回落两列，再在更窄窗口变成单列，节奏不散。
10. hover 卡片，确认只有轻微抬升和色温变化，没有网页营销卡片的强动效。
11. 点击任一卡片，确认输入框拿到对应 prompt。
13. 观察第四色卡插画，确认它明显是“接入/连接”语义，而不是另一张托盘卡。
14. 观察四色卡面，确认颜色更丰富，但仍然像桌面模块，不像营销海报。
15. 观察品牌区，确认字标下只保留一行副标题，没有额外解释句。
16. 观察卡片留白，确认品牌区到卡片区之间有明确呼吸感，但首屏高度仍然紧凑。
17. 观察字标，确认它已经退出普通文本渲染语义，视觉上更接近 `QClaw` 的品牌头结构。
18. 观察字标，确认它不再是粗糙的手绘描边骨架，而是更稳定、干净的品牌图式字形。
19. 观察字标，确认 `X` 和 `Claw` 看起来像同一家族，而不是“单独一个 X + 另一套字”。
20. 在浅色与深色主题下各检查一次，确认没有破坏既有桌面层级。
21. 在真实桌面窗口下观察一次，确认页面看起来是应用内页，而不是宣传页。
22. 放大缩小页面或调整窗口宽度时，确认字标仍然保持视觉居中，不会因为素材透明留白或旧比例写死而偏向一侧。
