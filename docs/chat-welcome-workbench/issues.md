# 聊天欢迎态桌面工作台问题记录

## 已知问题

1. 真实桌面窗口下的手工视觉 smoke 还没做，当前只完成了定向自动化校验。
2. 主视觉虽然已按线上 OpenClaw 结构和动画参数还原，但是否达到肉眼上的“100%一致”，仍需在真实运行窗口中直接对照线上页面确认。
3. 用户已追加接受低频 special-idle 伪 3D 增强，因此当前版本不再是严格意义上的“只做线上还原”；如果后续要回到纯还原版，需要去掉这层增强。
4. 四张卡在更窄窗口下虽然会回落为两列再到单列，但是否仍然保有足够的桌面感，还需要人工确认。
5. 英文和日文文案已经同步，但自然度仍应在实际语言环境中继续检查。
6. 四张卡已经拉开为更丰富的四色面板，但不同平台下的阴影与高光强度仍需要真实窗口人工确认。
7. `QClaw` 欢迎头是 `logo` 图片加副标题，不是纯文字标题；如果后续再把品牌图误当成字体去追，会再次把欢迎页标题判断带偏。

## 本次明确拒绝的方向

1. 不把欢迎态做回 `QClaw` 式五张生活场景卡。
2. 不把聊天起始页做成功能广告位或产品首页。
3. 不保留编号、箭头等“建议列表”式装饰。
4. 不为了做品牌主视觉而扩大整页光晕。
5. 不用“差不多像”的静态 SVG 替代线上动态资产。
6. 不把线上 Hero 的整块深色背景横幅直接移植到聊天欢迎态。
7. 不保留与当前主题背景割裂的局部黑色雾团。
8. 不做高频、整圈旋转或强表演式 3D 动画。
9. 不在品牌标题下重新塞回第二段欢迎说明文。
10. 不让 `接上能力` 和 `直接开工` 继续共用近似托盘插画。

## v1 接受的取舍

1. 继续使用内联 SVG 与纯 CSS 抽象插画，不建设完整插画资源体系。
2. 先固定为 4 张工作模式卡，不继续扩展更多模板。
3. 主视觉背景只截取局部星点与星云层，不复制线上整页 Hero 布局。
4. 伪 3D 只用 CSS 透视、位移、旋转和影子实现，不引入 WebGL。
5. 先只调整欢迎态，不继续修改消息区和输入区主体结构。

## 后续观察项

1. `直接开工 / 接着往下 / 拆开推进 / 接上能力` 这四张卡的中文标题是否还需要进一步压缩。
2. Windows 平台下边框、阴影和 hover 强度是否需要单独补偿。
3. `多个 Agent` 这类产品词在非中文语言环境中是否还需要更贴近本地用户习惯。
4. 是否需要把主视觉尺寸再向线上页面做桌面宽度下的像素级对齐。
5. `17s` 的 special-idle 周期是否还需要继续拉长，避免用户长时间停留时觉得动作偏多。
6. 第四张 `接上能力` 卡的能力边界是否还需要再往 `Skill` 或 `工具接入` 方向压得更明确。
7. 四张卡当前的中文说明句是否还需要继续压短，以进一步贴近桌面应用的冷静语气。
