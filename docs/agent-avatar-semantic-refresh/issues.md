# 智能体头像语义化重构问题清单

## 当前已确认问题

### 1. 现有头像没有角色语义

当前头像只保证稳定，不保证“像这个智能体”。

### 2. 市场已有 `avatarSeed` 但没有真正进入渲染链路

这导致数据上看起来有准备，实际 UI 仍然按 `id` 画占位符。

### 3. 本地智能体有 `SOUL.md`，但头像系统没有使用

这说明当前链路浪费了最有价值的角色信息。

### 4. 直接照搬 control-center 会造成风格割裂

它的像素动物和 XClaw 现有工作台语法不属于同一种产品语言。

## 已收敛结论

### 1. 不走远程 DiceBear API

原因：

- 离线能力会变差
- 会引入外部依赖
- 本地智能体信息不应该发到外部服务

### 2. 不复刻 control-center 的像素表现层

原因：

- 风格不对
- 判定逻辑仍然过度依赖 `agentId`

### 3. 采用 DiceBear 本地库 + `bottts-neutral`

这是当前最符合 XClaw 产品气质的路线。

### 4. 语义判定坚持规则引擎，不用 AI

原因：

- KISS
- 可测试
- 离线
- 不会因为提示词或模型变化而漂移

## 已落地决策

- 本地语义材料按 `SOUL.md -> IDENTITY.md -> AGENTS.md` 的优先级读取首个可用文件
- `avatarProfile` 已成为本地快照与市场 catalogue 合同的一部分
- DiceBear 渲染保留在 renderer，语义判定保留在共享纯函数和 Electron 富化层

## 仍需关注的问题

### 1. 规则词典精度仍受模板质量影响

如果市场模板的 `summary / role / tags` 质量不高，archetype 只能退化到较宽泛的类别。

### 2. 本地 persona 文件目前不做合并解析

当前实现只读取首个可用文件，不做多文件融合。

### 3. fallback 仍然是无语义 identicon

这保证了稳定和兜底，但对完全缺少语义材料的 agent，视觉表达仍然只是“稳定占位图”。

## 当前最高优先级

1. 在真实界面里人工走查一轮典型 archetype
2. 根据真实市场模板质量决定是否微调关键词词典
3. 观察用户是否需要更强的 persona 差异度

## 当前风险

### 1. 关键词词典如果过度扩张，会违反 KISS

必须克制在少量 archetype 和少量核心关键词，不做假智能。

### 2. 如果直接把完整 `SOUL.md` 暴露到前端，会扩大数据面

这不必要，也不符合最小暴露原则。

### 3. 如果没有旧 identicon fallback，新头像链路失败会直接变成空白

这不能接受，必须保留兜底。
