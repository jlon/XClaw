# 频道中心重构问题跟踪

## 当前已知问题

### 1. `/verbose` 暂无清晰频道级持久化边界

当前证据更支持将 `/verbose` 视为会话或运行行为，而不是所有渠道都稳定支持的频道配置项。

本轮处理：

- 先不纳入 v1 频道中心
- 若后续要做，需单独定义“回复行为预设”模型，而不是硬塞进凭证表单

### 2. 各渠道高级字段支持度并不一致

虽然通用高级会建立统一分组，但并不是每个渠道都支持全部字段。

本轮处理：

- 使用按渠道能力显隐的字段 registry
- 禁止为了视觉整齐而展示没有后端落点的开关

### 3. 旧 `getChannelFormValues()` 对结构化字段支持不足

当前回填逻辑主要覆盖：

- 通用字符串字段
- Telegram `allowedUsers`

数组、布尔、数字类高级字段如果要进 UI，必须先补读写适配。

本轮处理：

- 保留 `getChannelFormValues()` 给旧 modal 兼容路径使用
- 新增 `getChannelEditorValues()` 给工作台回填布尔、数组、数字值
- 工作台优先走 editor-values 路径，避免把旧字符串表单链硬拽成通用协议
- 当前已展示的插件参数字段，统一依赖这条链路并在 registry 中按真实证据标注为 `current-xclaw-roundtrip`

### 4. 旧 modal 仍有过渡兼容成本

当前页面和潜在外部调用仍依赖 `ChannelConfigModal`。

本轮处理：

- 页面主流程退场 modal
- modal 先保留为兼容壳
- 待工作台稳定后再进一步收缩

### 5. 高级配置过多容易重新变成设置墙

如果直接把所有字段一次铺开，页面可用性会再次恶化。

本轮处理：

- 高级区默认折叠
- 使用摘要显示关键状态
- 渠道专属高级继续按主题拆组

### 6. 工作台切换可能吞掉未保存输入

三栏结构带来了更自然的切换路径，但如果没有编辑态保护，用户也更容易在切换频道 / 账号时丢失当前输入。

本轮处理：

- 切换频道或账号前，如果右栏存在未保存修改，先弹确认
- 保存成功后重新拉取 editor-values，避免服务端标准化后的值仍停留在旧前端状态

### 7. 新增账号保存后可能停留在旧账号

如果新增账号后页面仍停留在旧账号，用户会误以为“刚才没有保存成功”或“新账号被吃掉了”。

本轮处理：

- modal 保存成功时把最终 `channelType + accountId` 回传给页面
- 页面刷新账号列表后自动选中该账号
- e2e 新增一条真实 smoke，验证“新增账号后直接落到新账号”

### 8. 频道页字段缺少显式 label 绑定

右栏工作台已经是主编辑入口，如果表单标签没有和输入框建立明确关联，e2e、键盘导航和辅助技术都会更脆。

本轮处理：

- 为工作台内联字段补齐 `label -> input/select` 绑定
- 优先按字段名称定位，而不是继续依赖 placeholder 或 DOM 结构猜测

### 9. 首屏加载默认主动 probe，导致进入频道页偏慢

频道页原先每次请求 `/api/channels/accounts` 都会强制 `channels.status { probe: true }`。当网关刚启动、网络抖动或运行态响应慢时，首屏会被这次主动探测拖慢。

本轮处理：

- `/api/channels/accounts` 默认改为 `probe=false`
- 仅在用户点击“刷新”时走 `?probe=1`
- 网关不在 `running` 时，直接跳过 runtime rpc

### 10. 左右留白和内容拥挤并不只是频道页局部问题

这次截图暴露的问题不是单个卡片写错，而是全局 `MainLayout` padding 与频道页自身 `max-width + padding` 叠加，导致宽屏下左右浪费空间，而三栏内部又被挤得过密。

本轮处理：

- 缩小 `MainLayout` 全局主内容区横向 padding
- 去掉频道页固定 `max-w-5xl` 和过厚外层内边距
- 重新分配三栏宽度比例，并让按钮区 / 行为区支持换行

### 11. 频道文案偏实现视角，不够人话

像“绑定对象”“ID:”这类文案更像开发内部术语，不像面向用户的频道管理语言。

本轮处理：

- 把账号、Agent、连接状态相关文案改成人话表达
- “绑定对象”统一收敛为 “Agent / 由谁负责处理消息”
- 补一条中文 locale 单测，防止后续再回退到技术术语

### 12. 浏览器态自动化已补齐，但 Win/mac 真机体验仍需手工确认

当前自动化已覆盖：

- 频道页浏览器态单测
- 主题切换相关 smoke
- 浅色 / 深色 Playwright smoke

但这还不等于 Win/mac 真机体验已经全部证明。

本轮处理：

- 代码层面已把页面滚动、内容留白、表单换行、Windows 滚动条策略一起收敛
- 自动化里新增了共享壳层与主内容区滚动边界约束
- 仍需要在 macOS 与 Windows 真机下做一次手工 smoke，重点看系统缩放、系统字体和 Electron preload 环境下的最终表现

### 13. 账号标识编辑如果只改前端显示，会破坏默认账号和 Agent 绑定

账号标识实际是 `accounts[accountId]` 的 key，不是普通展示名。如果只允许前端改输入框、不做后端真实迁移，就会留下三类错误：

- `defaultAccount` 仍指向旧账号 ID
- 顶层镜像字段仍停留在旧默认账号
- Agent 绑定仍挂在旧 `channel + accountId` 上

本轮处理：

- 新增独立 rename 路由
- 配置层新增 `renameChannelAccountConfig()`
- 绑定层新增 `renameChannelAccountBinding()`
- 页面保存时先 rename，再保存当前配置，并保持焦点停在新账号

### 14. 左栏状态和右栏说明文案如果过于抽象，会继续制造“绿点误解”和缩放错位

此前左栏主要靠彩点表达状态，右栏部分字段说明又偏长，导致两个直接问题：

- 用户会把彩点误解成“平台支持”而不是“当前连接状态”
- 缩放后说明文字把输入框和下拉框挤得错位

本轮处理：

- 左栏状态摘要改为同时显示账号数、连接状态、启停状态
- 右栏账号标识和负责 Agent 改成显式 label + 紧凑控件
- 字段说明统一限制为最多两行，减少高缩放下的布局漂移

### 15. 基础配置在中等宽度提前双列，会把账号标识和字段标签挤成竖排

之前基础配置区在 `md` 断点就切双列，右栏可用宽度还不够时，账号标识说明、默认账号 badge、Bot ID / Secret 标签会被压成很窄的列，看起来像“文字竖排 + 大块空白”。

本轮处理：

- 基础配置改为到 `xl` 才切双列
- 账号标识卡片改回单列纵向布局
- 无说明文字的字段不再强行保留固定最小高度

### 16. 原生 `select` 会把频道页多个区块一起拖回系统样式，并放大错位问题

最新截图暴露的“负责 Agent 箭头错位”“访问控制下拉框压住说明”“展开后还是系统原生菜单样式”并不是三个独立 bug，而是同一个共享控件问题：

- 频道页仍在复用原生 `<select>`
- mac 下展开后直接回到系统菜单外观，和页面主题完全脱节
- 不同平台的原生箭头、行高、内边距不一致，导致右栏行为区和访问控制区一起错位

本轮处理：

- 把频道页所有下拉统一切到共享自定义 Select
- 端到端补一条 smoke，明确约束“频道页不再出现原生 `<select>`”
- 统一下拉触发器、列表面板和选中态样式，保证暖色 / 深色主题及 mac / Windows 下的一致性

### 17. 中栏头部动作区如果继续自由换行，会制造大块空白和层级漂移

“添加账号”和删除频道原先使用松散的 `flex-wrap` 容器，在特定宽度和缩放下会出现：

- 添加账号按钮单独占一行
- 删除按钮被挤到下一行
- 右上角留出明显空白，视觉上像布局坏了

本轮处理：

- 中栏头部动作区改成紧凑的单行动作组
- 让动作组整体右对齐、自身不再自由换行
- 通过单测锁定这条布局约束，避免后续回退

### 18. 频道页如果只做“单栏 / 三栏”粗断点，默认窗口下右栏会被挤压

此前频道页在 `xl` 直接切到三栏，窗口稍微缩小又退回单栏，这会带来两个直接问题：

- 默认窗口宽度下第三栏可读宽度不稳定，用户需要手动放大窗口才能完整操作
- 缩放时缺少稳定过渡态，布局会在“硬挤三栏”和“整页上下堆叠”之间跳变

本轮处理：

- 工作台改为“单栏 / 两栏 / 三栏”三段式响应布局
- 标准窗口下优先展示“导航栈 + 编辑区”两栏，不再默认硬挤三栏
- 只有超宽工作区才把频道导航和账号列表拆成独立两栏
- 用单测锁定两栏过渡和 `2xl` 才进入三栏的规则

### 19. 默认窗口继续优先“两栏工作台”，会和 QClaw 实码及真实任务模型冲突

这轮进一步对照 QClaw 实码后，确认问题不只是“断点不够细”，而是信息架构前提本身就错了：

- QClaw 的首屏是 `remote-channel-grid + remote-channel-card` 入口板，不是默认两栏工作台
- 默认窗口下用户的第一任务是“选频道”，不是同时管理频道、账号和表单
- 如果继续坚持默认两栏，只会把频道发现和编辑两个任务都做坏，并逼着实现回到“伪卡片长列表”

本轮处理：

- 默认窗口改为频道入口卡片板
- 选中频道后进入聚焦编辑态，而不是默认持久保留频道总导航
- 只有内容容器达到约 `1600px` 时，才切到完整三栏工作台
- 缩放时先在“入口板 / 聚焦编辑态 / 三栏工作台”之间有序切换，不允许直接丢上下文

### 20. 入口卡片如果复用账号摘要和共享搜索状态，会在首屏泄露错误语义

入口卡片板落地后，很快暴露出两个新的边界问题：

- 已配置卡片直接复用了 `accountListSummary`，把默认账号 ID 这种账号级细节带到了首屏
- 入口板搜索和工作台左栏搜索共用同一个状态，用户从入口板筛选后进入频道，工作台会带着旧筛选条件“静默隐藏”其他频道

本轮处理：

- 入口卡片说明统一改成渠道级 `entryBlurb`，强调接入方式和使用场景，不再展示默认账号标识
- 已配置卡片把账号数放回聚合 badge，而不是写进说明文本
- 入口板搜索与工作台左栏搜索拆成两套状态，跨模式切换不再串味
- 单测新增覆盖“入口板筛选后进入频道，工作台搜索应为空且其他频道仍可见”

## 未决问题

### 1. 通用高级首批字段的最终名单

当前已纳入：

- 渠道启停
- 默认账号
- Agent 绑定
- Feishu / WeCom / DingTalk 的已闭环基础与访问控制字段
- 插件源码已定义、且当前工作台已能通过 `saveChannelConfig -> getChannelEditorValues` 回填的字符串 / 布尔 / 数组 / 数字 / 枚举字段

仍需继续观察：

- 更复杂的嵌套结构字段，例如 `replyMode`、`footer`、`groups`
- 会话级命令开关，例如 `/verbose`
- 清空某些可选字段时，是否需要增加显式“重置 / 清除”动作，而不是仅靠空字符串覆写

### 2. 首屏默认选中策略是否需要持久化

当前建议优先级：

1. 入口板模式下不自动选中
2. 进入聚焦编辑态或三栏模式时，优先最近操作渠道
3. 再回退到首个已配置渠道
4. 最后回退到首个主推渠道

是否把最近选中渠道持久化到本地 store，可在实现时视复杂度决定。

## v1 接受的取舍

- 不追求所有渠道高级配置完全对齐
- 不在本轮引入全新的后端编辑协议
- 不在本轮处理所有命令级行为开关

## 后续观察项

- Windows 下三栏滚动表现是否需要单独细调
- 如果高级字段继续增加，是否需要把当前页面内摘要 helper 抽成统一 formatter
- 渠道帮助文档入口是否需要做成右栏上下文文档卡片
- 是否需要继续把端到端 smoke 扩到“删除账号 / 默认账号切换 / 验证失败态”
- 缩放到更高系统字号时，右栏行为区是否需要进一步拆成两行卡片
- Electron 真机窗口下，暖色 / 深色主题切换时的 hover 与滚动条体感是否还要继续微调
- Windows 真机下“入口板 / 聚焦编辑态 / 三栏工作台”切换时，内容高度和滚动表现是否还需要单独收敛
- 账号标识 rename 后，是否需要继续补一条 Electron 真机 smoke，专门覆盖默认账号切换 + Agent 绑定回读
