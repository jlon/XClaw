# Agent 工作台重构设计

## 背景

当前 `Agents` 页的问题，不是“功能不够多”，而是产品形态错了。

之前的方向是：

- 左侧 `source list`
- 右侧工作台
- 在右侧再叠 `概览 / 人格文件 / 市场`

这套结构可以勉强承载 CRUD，但做不出桌面级质感。  
原因很直接：

- 左侧列表仍然像后台资源列表
- 人格文件编辑被挤进窄 pane，编辑体验天然差
- 市场与本地 Agent 混在同一套布局里，发现和编辑两种任务流互相打架
- 页面主视觉总是落在“选项列表”，而不是当前 Agent 本身

这次不能继续做“更漂亮的后台”。  
必须把 `Agents` 升级成真正的 **Agent 工作台**。

## 真实证据

### 1. XClaw 当前已有的真实能力

当前真实已存在：

- Agent CRUD
- 频道绑定摘要与跳转
- `workspace` 文件接口
- 市场 catalogue 与安装
- 安装回滚与 runtime refresh

对应代码：

- `src/stores/agents.ts`
- `electron/api/routes/agents.ts`
- `electron/api/routes/agent-market.ts`
- `electron/utils/agent-config.ts`
- `electron/utils/agent-market.ts`

这说明我们已经不是“只有列表页”的阶段了。  
真正缺的是 **合理的工作台布局**，不是更多接口。

### 2. 人格文件是真实资产，不是表单字段

本机 agent 目录下存在真实文件：

- `SOUL.md`
- `AGENTS.md`
- `TOOLS.md`
- `USER.md`
- `IDENTITY.md`
- `HEARTBEAT.md`
- `BOOT.md`

这些文件位于 `workspace` 受控根目录。  
这证明 Agent 详情页不能继续只做几块输入框，它必须是一个真实资产工作区。

### 3. `agentDir` 与 `workspace` 不是同一权限层

当前后端已经把两类根目录分开：

- `workspace`：可编辑的 bootstrap 资产
- `agentDir`：runtime 配置事实面

所以设计上必须继续守住：

- `workspace` 才是编辑面
- `agentDir` 只做事实展示，不开放写入

### 4. QClaw 可吸收的是结构，不是像素皮

本机 `QClaw` 解包源码里，没有一个可直接照抄的 Agent 页面。  
但它的 `技能管理 / 详情面 / 设置面板` 已经给出了两条很清楚的规律：

- **发现与选择** 用卡片面或轻列表面
- **深入编辑** 用单一 detail pane / inspector

尤其技能管理页面的卡片结构，已经证明：

- 卡片适合“浏览、发现、筛选、安装”
- 详情面板适合“查看细节、执行动作”

因此，`Agents` 正确的形态应该是：

- 本地 Agent：卡片式浏览
- 右侧详情：工作区式编辑
- 市场：独立卡片面

而不是继续把所有任务都塞进一个 source list。

### 5. 本地头像不是装饰，是识别资产

用户明确提出：

- 市场里的 Agent 要有卡片式头像
- 本地 Agent 也要有更强的识别感

这点不能靠“首字母圆球”继续糊弄。  
但也不能走在线 AI 出图，因为：

- 不稳定
- 不可离线
- 不利于桌面 app 一致性

因此头像方案必须满足：

- 本地生成
- 可重复
- 跨平台稳定
- 不依赖联网
- 能根据 Agent 特征生成差异化视觉

### 6. 市场摘要和详情必须来自真实源文件，不做假文案

`Agent 市场` 里的摘要、亮点、详情不能靠手写一句 `role` 糊弄，也不能靠目录名拼凑。

这轮已经确认：

- 上游 `agents.json` 只提供浅层索引
- 准确的摘要与详情必须从各模板真实 `SOUL.md` 解析
- 市场 seed 需要预先富化，至少包含：
  - `headline`
  - `summary`
  - `highlights`
  - `detailSections`
  - `tags`
  - `avatarSeed`
  - `localeKey`

因此 v1 的正确策略是：

- **内容事实**：来自上游 `SOUL.md`
- **界面国际化**：由本地 i18n 控制
- **没有本地化内容时**：保留源语言，而不是生成不可信假翻译

这条边界必须写死。否则市场页会再次退回“看起来像有内容，实际上不可信”的假商店。

## 设计目标

把 `Agents` 重构成一个桌面级 Agent 工作台，满足三种核心任务：

1. 浏览并管理我的 Agent
2. 编辑当前 Agent 的人格文件与核心配置
3. 从市场发现并安装新的 Agent

同时满足：

- 保持 `QClaw substrate, XClaw accent`
- 不做网页后台
- 不做“大而全文件管理器”
- 不引入假市场或假头像

## 非目标

- 不做开放社区市场
- 不做评论、评分、社交关系
- 不做在线图片生成头像
- 不开放 `agentDir` runtime 文件写入
- 不在 v1 做版本历史、diff、多人协作
- 不做拖拽复杂看板

## 产品原则

### 1. 发现和编辑必须分层

`QClaw` 做得舒服，不是因为“卡片多”，而是：

- 发现阶段看资源卡
- 决策阶段看详情
- 操作阶段进入单一工作区

所以这次必须避免两种错误：

- 所有东西都做成卡片
- 所有东西都塞进右侧窄详情栏

正确做法是：

- 资源卡负责选择
- 详情负责理解和执行
- 文件编辑负责深度修改

### 1.1 模式切换只负责切模式

`我的 Agents / Agent 市场` 必须是轻量 segmented switch：

- 只负责切模式
- 不承担搜索、筛选、计数、说明文案
- 不和安装/创建动作混成同一语义层

搜索、筛选、创建、安装相关动作，全部留在各自模式的浏览工具条里。

### 2. “我的 Agent”和“Agent 市场”不是一个页面状态

这两者虽然都和 Agent 有关，但任务目标不同：

- 我的 Agent：维护、编辑、绑定、删除
- Agent 市场：浏览、筛选、预览、安装

所以它们必须是两个清晰的工作模式，而不是同一个面里混杂。

### 3. 人格文件编辑必须是主任务区，不是弹窗

`SOUL.md / AGENTS.md` 这类文件的编辑属于高价值主任务。  
不能继续塞进：

- modal
- 小抽屉
- 右侧过窄 info pane

正确做法是：

- 右侧 detail pane 负责承接
- 编辑区在 detail pane 中占主面积

### 4. 头像必须是本地、可重复、可识别的

头像不是“为了好看”。  
它要解决三个问题：

- 市场卡片的第一眼辨识
- 本地 Agent 的快速识别
- 不同角色之间的视觉区分

所以必须使用：

- deterministic
- offline
- low-noise
- desktop-friendly

### 4.1 国际化支持必须区分“壳层文案”和“内容文案”

用户要求市场支持国际化，这里不能偷换概念。

v1 当前真正能承诺的是：

- 搜索、按钮、分组、章节标题、安装面板等壳层文案支持 `zh / en / ja`
- 模板 `name / headline / summary / highlights / detailSections` 支持走 locale key 查找
- 当某个模板还没有人工校对过的多语内容时，继续回退到上游源语言

不能承诺的：

- 首批内置模板已经扩大到 58 条，中文内容优先覆盖高频模板；英文和日文继续按壳层本地化、安全回退
- 自动机翻后的内容可以替代原始说明

所以国际化实现必须是：

- **先保证准确**
- **再允许本地化覆盖**
- **默认回退到源语言**

### 5. 卡片不是网页卡片，必须是桌面卡片

这次如果还做成：

- 大阴影
- 厚玻璃
- 大渐变
- 到处发光

就会再次回到网页感。

桌面级卡片的原则是：

- 更紧
- 更稳
- 信息密度高但不吵
- hover 与选中反馈明确
- 背景与边界克制

### 6. 市场内容必须以真实模板为准，国际化不能伪造

`Agent 市场` 不是目录浏览器，也不是营销页。  
每个模板都必须能回答三件事：

- 它是谁
- 它擅长什么
- 它具体会怎么工作

所以市场页的数据合同不能只停留在：

- `name`
- `role`
- `sourcePath`

必须升级为：

- `headline`
- `summary`
- `highlights`
- `detailSections`
- `tags`
- `avatarSeed`
- `localeKey`

这些字段的事实来源已经确定：

- 上游 `agents.json` 只负责索引
- 准确摘要和详情来自真实 `SOUL.md`
- 本地 seed 负责把这些内容固化成受控 catalogue

国际化也必须按真实边界做：

- `zh / en / ja` 负责壳层和章节标题
- 模板内容允许 locale key 覆盖
- 没有覆盖时保留源语言

不能因为“要支持国际化”就直接把所有模板内容机翻塞进市场。  
那会再次回到“不准确但看起来很多”的假完成。

## 信息架构

## 总体结构

采用 `一页双模式 + 自适应双工作区` 的结构：

1. 顶部模式切换
   - `我的 Agents`
   - `Agent 市场`
2. 左侧主浏览区
3. 右侧 detail workbench

### 模式 A：我的 Agents

本地模式不再退回单列资源卡。  
正确结构是：

- 左侧：**自适应卡片浏览区**
- 右侧：**当前智能体 detail workbench**

浏览区和 detail workbench 同时存在，但比例会随窗口宽度变化。

### 模式 B：Agent 市场

市场模式继续保留卡片浏览，但不再复用本地模式的管理语法。  
结构是：

- 左侧：市场卡片墙
- 右侧：模板详情与安装动作

### 响应式规则

本地模式真正需要学习的不是“卡片”，而是 **浏览区宽度重新分配**：

- `>= 1500px`
  - 左侧浏览区显示 `3` 列卡片
  - 右侧 detail 常驻
- `1200px - 1499px`
  - 左侧浏览区显示 `2` 列卡片
  - 右侧 detail 常驻
- `980px - 1199px`
  - 左侧浏览区退回 `1` 列卡片
  - 右侧 detail 继续可见
- `< 980px`
  - 浏览与详情切成单列承接
  - detail 改成覆盖式/切换式承接，而不是硬挤

标准窗口下的预期比例：

- 左侧浏览区：`58%-62%`
- 右侧 detail：`38%-42%`

这里的“标准窗口”不是抽象概念，而是当前 Electron 默认主窗口：

- `1200 x 800`

因此，设计红线要明确绑定到当前产品事实：

- 默认窗口下，本地模式优先看到 `2` 列卡片
- detail workbench 继续常驻
- 不能退回“一行一个智能体”

## 模式 A：我的 Agents

### 上部工具栏

包含：

- 搜索
- `新建智能体`
- `从市场安装`

注意：

- `设置` 不进入这里
- `duplicate` 不在 v1 暴露成头部主按钮，等 contract 锁死后再进

### 主浏览区：本地智能体卡片浏览区

不再使用 source list。  
也不再退回单列资源卡。  
改为 **自适应卡片浏览区**：

- 很窄窗口：1 列
- 标准窗口：2 列
- 更宽窗口：3 列

每张卡片显示：

- 专属头像
- 智能体名称
- 当前模型
- 绑定频道数量
- 默认/继承标记

一行角色摘要只在 **存在可信摘要** 时显示：

- 来源可以是已解析的人格文件摘要
- 或者已存在的受控 market/detail 文案

如果当前本地智能体没有真实摘要，就不要假生成一句话，不要为了“卡片更满”制造假内容。

卡片不展示：

- `workspace path`
- `agentDir`
- 过长的内部 id
- 调试字段

卡片动作：

- 单击选中
- hover 露出轻操作：
  - 打开
  - 更多

卡片不直接堆：

- 删除
- 大按钮组
- 太多 badge

浏览区的职责只有三件事：

- 发现
- 选择
- 快速创建

不能再次退回“把所有管理动作都堆回卡片”。

### 右侧：Agent Detail Workbench

右侧是唯一主工作区，分三段：

#### 1. Header

显示：

- 头像
- 名称
- 简短角色摘要
- 默认状态
- 模型

动作：

- `开始对话`
- 改名
- 删除
- 打开工作区
- 显示到 Finder / Explorer
- 进入频道绑定编辑

其中：

- `开始对话` 是唯一主动作
- 其余都是次级 utility action

#### 2. Segment Tabs

固定为：

- `概览`
- `人格文件`
- `绑定与运行`

#### 3. 当前内容

##### 概览

显示：

- 智能体简介
- 来源
- 绑定频道摘要
- 工作区路径事实面

##### 人格文件

主内容区：

- 左：文件切换条
- 右：编辑器

支持：

- 保存
- `Cmd/Ctrl+S`
- 上传替换
- 新增文本文件
- 重命名
- 删除非保留文件

##### 绑定与运行

只展示真实能力：

- 绑定频道摘要
- 去频道页编辑
- runtime 状态事实

不做假控制台。

## 模式 B：Agent 市场

### 上部工具栏

包含：

- 搜索
- 类别筛选
- 来源筛选
- “仅看可安装”

### 主浏览区：市场卡片墙

布局与本地模式共享同一 substrate，但信息更偏“发现”：

每张卡片显示：

- 专属头像
- 名称
- 角色
- 一行卖点摘要
- 来源标签
- 安装模式

状态：

- 未安装
- 已安装
- 可更新（如后续支持）

市场卡片和本地卡片的差别必须明确：

- 本地卡片偏“管理与选择”
- 市场卡片偏“发现与安装”

不能为了统一而把两者做成同一种信息密度。

### 右侧：市场详情面

显示：

- 头像
- 名称
- 角色
- 长介绍
- 来源仓库
- 安装将生成哪些文件
- 安装后的默认 Agent id/名称建议

动作：

- 一键安装
- 安装后跳转到“我的 Agents”

## 头像方案

## 设计目标

本地 Agent 和市场 Agent 都需要统一的专属头像体系：

- 不依赖联网
- 可重复生成
- 同一个 Agent 永远得到同一张头像
- 根据角色/类别差异生成不同视觉
- 风格稳定，适合桌面 app

## 备选方案评估

### 方案 A：首字母圆章

优点：

- 实现最简单

问题：

- 太像占位头像
- AI 味重
- 市场卡片辨识度太低

结论：

- 不采用

### 方案 B：几何 identicon / 外部库

候选：

- `jdenticon`
- `dicebear`

优点：

- 生态成熟
- deterministic
- SVG 输出稳定

问题：

- `jdenticon` 更像系统账户头像，角色感弱
- `dicebear` 风格漂移风险偏高，更像插画角色，不够贴当前桌面工作台气质
- 引入外部库不能直接提升产品价值，反而会扩大视觉合同

结论：

- v1 不切库
- 仅作为后续备选

## v1 推荐头像策略

采用：

- 继续保留当前自研 deterministic 头像
- 如后续确有收益，再评估 `jdenticon`

生成规则：

- 主种子：`agent.id`
- 本地与市场在相同 seed 规则上做轻差异映射
- 色板继续基于 `XClaw accent` 的克制色板

这样可以做到：

- 不联网
- 不需要 AI 出图
- 不扩大依赖面
- 跨平台稳定
- 同一智能体视觉不会漂移

## 动线设计

### 1. 新建空白 Agent

1. 进入 `我的 Agents`
2. 点击 `新建智能体`
3. 生成空白卡片
4. 右侧自动进入该 Agent 的 `概览`

### 2. 编辑人格文件

1. 在卡片墙里选择一个 Agent
2. 右侧进入 detail pane
3. 切到 `人格文件`
4. 编辑并保存

### 3. 从市场安装

1. 进入 `Agent 市场`
2. 浏览卡片或搜索
3. 右侧查看详情
4. 安装
5. 自动跳回 `我的 Agents`
6. 新 Agent 卡片高亮选中

## 兼容原则

### mac / Windows / Linux 红线

必须保持：

- 同一套布局逻辑
- 不依赖单平台控件
- 字体、滚动条、hover 仅做轻平台适配
- Linux 也必须保持可用，不允许因为只盯 mac/Windows 把布局写死

不能做：

- 只在 mac 上成立的玻璃态
- 只在 Windows 上成立的特定标题栏依赖

## v1 范围

### 必做

- `我的 Agents` 自适应卡片浏览区
- `Agent 市场` 卡片墙
- 右侧 detail workbench
- 人格文件真实编辑
- 本地 deterministic 头像

### 暂缓

- duplicate
- 开放社区市场
- 评论/评分
- 在线头像生成
- 版本历史

## 成功标准

如果设计正确，最终效果应该满足：

- 本地 Agent 第一眼更像“可操作的角色卡”，不是后台资源条目
- 市场第一眼更像“可安装的模板商店”，不是后台表格
- 人格文件编辑是主工作区，不是挤在小窗里
- 页面整体更像桌面 app 的工作台，而不是网页后台

## 三轮设计复盘结论

### 第一轮：信息架构复盘

结论：

- 旧的 `source list + 右侧 pane` 必须废弃，不能继续微调
- `我的 Agents` 与 `Agent 市场` 必须是两个顶层模式，不再塞进右侧 tab
- 右侧 detail workbench 继续保留，但只服务“当前选中对象”

确认后的结构：

- 顶部模式切换
- 中间浏览区
- 右侧 detail workbench

### 第二轮：布局与动线复盘

结论：

- “发现”和“编辑”不能共享同一视觉重心
- 浏览区卡片负责发现与选择
- detail pane 负责理解、安装、编辑和执行
- 人格文件编辑区必须在右侧 pane 内占主面积，不再被压成小模块

确认后的交互：

- 点击本地 Agent 卡片 -> 右侧进入该 Agent 的工作区
- 点击市场 Agent 卡片 -> 右侧进入该 Agent 的市场详情
- 市场安装完成 -> 自动切回“我的 Agents”并高亮新卡片

### 第三轮：桌面质感与识别系统复盘

结论：

- 卡片式不等于网页卡片
- 桌面级卡片必须更紧、更稳、更少装饰
- 本地 Agent 和市场 Agent 都需要稳定头像系统
- 头像不能在线生成，必须 deterministic 且离线可用

确认后的头像策略：

- v1 保留当前自研 deterministic 头像
- 主种子使用 `agent.id`
- 如后续确有收益，再评估 `jdenticon`
- 不在本轮切 `dicebear`

## 当前收敛后的最终版设计红线

1. 不再回到左侧 source list 主浏览
2. 不再把市场混进本地 Agent 编辑工作区
3. 不再把人格文件编辑塞进弹窗或窄列表布局
4. 不再使用首字母圆章作为最终头像方案
5. 不为了“统一入口”假做 duplicate
