## 当前问题

### 1. 结构是长网页，不是桌面设置面板

所有 section 被顺序平铺，阅读成本高，滚动中难以建立空间记忆。

### 2. 高频与低频任务权重混乱

`Gateway`、主题/语言、更新确认与 `About`、`Developer` 过去被拉平成同一阅读流，违背真实使用频率。

### 3. 开发者区过于“内容块化”

`proxy / doctor / telemetry` 都是重内容块，容易把页面拖回后台工具页。

### 4. 不应把 Providers 错放进 Settings

`ProvidersSettings` 当前真实挂在 `Models`。如果为了“像别的产品”把它再搬进设置页，会制造重复入口并破坏信息架构。

## 风险

### 1. 只换布局，不改节奏

如果只是加一个左侧导航，但右侧仍是原来的长页面卡片流，网页感仍会保留。

### 2. 开发者区过度前置

若 `Developer` 导航和普通设置同等显眼，会继续破坏产品重心。

### 3. 过度模仿 QClaw

`XClaw` 的设置项复杂度比 `QClaw` 高，不能机械复制其结构，需要保留 Provider / Gateway 这类本产品关键路径。

## 本轮准则

- 先调整信息架构，再调视觉细节
- 高频任务优先于“设计完整性”
- 小改动允许敏捷直改，但前提是有真实问题和明确证据
