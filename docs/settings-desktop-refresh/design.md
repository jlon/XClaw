## 背景

当前 `Settings` 页的问题不是单个控件难看，而是整体仍然像网页后台：

- 高频任务和低频任务被拉平成一条长页面
- `AI Providers`、外观偏好、Gateway 控制、更新、开发者诊断权重几乎一样
- 用户需要在滚动中寻找目标，不像桌面应用的稳定设置面板
- 视觉上虽然已经进入冷中性 substrate，但信息架构仍是 web settings center

`QClaw` 的可取之处不是“更多卡片”，而是：

- 桌面基底稳定
- 高频入口清楚
- 设置采用固定尺寸面板 + 稳定切换入口 + 单一内容面板
- 系统级设置和工作流级设置分层明确
- 面板、分组、行项和次级说明有清晰主次

## 目标

把 `Settings` 重构成更像桌面应用的设置工作区：

- 顶部是稳定的 tabs 工具带，不是内容滚动的一部分
- 下方只显示一个当前激活的设置 pane
- 外观/语言/启动项归为“通用偏好”
- Gateway/运行控制归为“运行环境”
- 更新保持次级
- 开发者工具保持可达，但不再抢主路径

## 产品原则

### 1. 高频优先

设置页最常访问的内容不是“关于”或“埋点查看器”，而是：

- 语言 / 主题
- Gateway 状态与日志
- 更新相关确认

所以页面必须首先围绕这些任务布局。

### 2. 系统设置与运行诊断分离

用户修改偏好时，不应该和代理诊断、doctor、proxy 等工程项混在同一阅读流中。

### 3. 保持桌面面板语法

沿用 `QClaw substrate, XClaw accent`：

- tabs 是桌面工具带语法
- 内容面板是稳定的 pane surface
- 不回到厚网页卡片和长滚动分隔线

### 4. 不做假复杂度

首轮不引入复杂的分栏状态同步、搜索过滤、动态折叠动画系统。先把结构和权重做对。

## 第一阶段落地范围

### 页面结构

- 顶部直接进入单层 tabs 工具带
- tabs 下方只渲染一个当前激活 pane
- 小窗口仍保持同一结构，不退回长页面锚点滚动
- 内容面板优先采用 `card + row`，而不是连续长表单

### 设置 tabs

首批 tabs：

- 通用偏好
- 运行环境
- 更新
- 开发者（仅 dev mode 解锁时显示）

交互合同：

- 点击直接切换当前 pane
- 同时只允许一个主 pane 处于激活态
- 不再依赖滚动定位和 section 高亮
- 风格参考桌面工具带，不做网页二级导航条

### 内容区

内容区继续保留现有功能，但按单激活 pane 重排：

- `Appearance + Language + LaunchAtStartup` 合并为“通用偏好”
- `Gateway` 与运行相关项合并为“运行环境”
- `UpdateSettings` 和自动检查/自动下载合并为“更新”
- `Developer` 单独放在最后，仅 dev mode 显示

### 通用偏好专项

`通用偏好` 不再允许保留“两张大表单卡 + 三条大 toggle”的网页式骨架。

#### 结构合同

- 首屏只保留两个 pane：
  - `主题 / 语言`
  - `启动项 / 匿名使用数据 / 开发者模式`
- `主题 / 语言` 必须共用一套 segmented row 语法，不能拆成两张互不相关的大卡
- 页头不允许保留“设置”或“配置您的 XClaw 体验”这类重复性标题/泛解释文
- 页级说明只允许出现在 section 头部，禁止把 `appearance.description` 继续复用成字段说明
- `启动项 / 匿名使用数据 / 开发者模式` 必须使用统一 row + switch 语法，不能再出现三条厚 toggle 卡

#### 对齐铁律

- `WU-01`：`通用偏好` 首屏只承担“修改偏好”这一条主任务
- `WU-03`：主题、语言和开关必须共享同一条 utility grammar
- `WU-04`：先删重复说明，再保留必要提示
- `WU-08`：默认桌面窗口下不依赖内部滚动条完成偏好修改

### 运行时控制台专项

这一轮只先把 `运行时与代理` 按桌面工作台重排，不继续在长设置页上做“缩 padding”。

#### 结构合同

- `运行时` 首屏只允许一个主任务：管理 `Gateway` 与本地代理
- 顶部不再使用 `3` 张重复指标卡，改成一条紧凑事实带
- 中部只保留一条工具带：`重启 / 查看日志 / 打开日志目录`
- `代理` 从 `开发者` 区迁回 `运行时`
- `代理` 默认只展示：
  - 启用开关
  - 代理服务器
  - 保存动作
- `HTTP / HTTPS / ALL_PROXY / 绕过规则` 仅在展开高级代理时显示
- 日志不再内联长展开，改为独立轻模态

#### 不允许继续出现的结构

- `状态 / 端口 / 自动启动` 在同一个 section 内重复出现两次
- `Gateway` 标题、描述和动作条重复出现
- 代理与控制台、Doctor、埋点查看器混在同一 section
- 通过内联日志块拉长设置页

#### 对齐铁律

- `WU-01`：运行时 section 只承担一个主任务
- `WU-02`：运行时主区只保留事实带、工具带、代理 pane 三层
- `WU-04`：先删重复说明，再保留必要图标
- `WU-08`：默认桌面窗口下不依赖内联滚动日志完成主任务

### Providers 的位置

`AI Providers` 不放进 `Settings`。

证据：

- 当前真实实现里 `ProvidersSettings` 挂在 `Models` 工作台，而不是设置页
- Provider 配置属于模型工作流，不属于系统偏好

因此设置页只需要在必要时提供跳转，而不应该复制一套 provider 管理入口。

### 对齐 `QClaw` 的证据

- `QClaw` 的设置入口在聊天侧栏底部齿轮按钮
- 打开后是固定尺寸面板，不是独立长页面
- 顶部切换入口稳定，主区主要由 `card + row` 组成
- 常见 row 语法是左侧“标题 + 说明”，右侧“开关 / 动作 / 值”

`XClaw` 不需要照搬它的弹层形态，但要吸收这套信息组织方式。

## 第二阶段方向

第一阶段只改结构和层级。第二阶段再继续收：

- Gateway proxy / doctor / telemetry 的次级视觉语言
- 设置页内部按钮、badge、日志块的一致性
- 与 `Models` 工作台之间的跳转关系

## 不做

- 不把设置页改成多层嵌套路由
- 不做全局搜索
- 不抄 `QClaw` 的像素布局
- 不把开发者工具默认前置到普通用户视线中心
