## 背景

当前 `Settings` 页的问题不是单个控件难看，而是整体仍然像网页后台：

- 高频任务和低频任务被拉平成一条长页面
- `AI Providers`、外观偏好、Gateway 控制、更新、开发者诊断权重几乎一样
- 用户需要在滚动中寻找目标，不像桌面应用的稳定设置面板
- 视觉上虽然已经进入冷中性 substrate，但信息架构仍是 web settings center

`QClaw` 的可取之处不是“更多卡片”，而是：

- 桌面基底稳定
- 高频入口清楚
- 设置采用固定尺寸面板 + 左侧菜单 + 右侧内容
- 系统级设置和工作流级设置分层明确
- 面板、分组、行项和次级说明有清晰主次

## 目标

把 `Settings` 重构成更像桌面应用的设置工作区：

- 左侧是稳定的设置导航，不是内容区的一部分
- 右侧是当前设置内容面板
- 外观/语言/启动项归为“通用偏好”
- Gateway/运行控制归为“运行环境”
- 更新和关于保持次级
- 开发者工具保持可达，但不再抢主路径

## 产品原则

### 1. 高频优先

设置页最常访问的内容不是“关于”或“埋点查看器”，而是：

- 语言 / 主题
- Gateway 状态与日志
- 更新与关于的轻确认

所以页面必须首先围绕这些任务布局。

### 2. 系统设置与运行诊断分离

用户修改偏好时，不应该和代理诊断、doctor、proxy 等工程项混在同一阅读流中。

### 3. 保持桌面面板语法

沿用 `QClaw substrate, XClaw accent`：

- 导航是 source-list / utility 语法
- 内容面板是稳定的 pane surface
- 不回到厚网页卡片和长滚动分隔线

### 4. 不做假复杂度

首轮不引入复杂的分栏状态同步、搜索过滤、动态折叠动画系统。先把结构和权重做对。

## 第一阶段落地范围

### 页面结构

- 顶部保留简洁标题和说明
- 内容区改为两列：
  - 左：设置导航
  - 右：内容面板
- 小窗口自动退回单列，但仍保留统一 section 结构
- 右侧内容优先采用 `card + row`，而不是连续长表单

### 设置导航

首批导航项：

- 通用偏好
- 运行环境
- 更新
- 关于
- 开发者（仅 dev mode 解锁时显示）

导航交互：

- 点击滚动到对应 section
- 当前 section 在导航中高亮
- 风格参考 `QClaw` source list，不做网页 tabs

### 内容区

内容区继续保留现有功能，但先做以下重排：

- `Appearance + Language + LaunchAtStartup` 合并为“通用偏好”
- `Gateway` 与运行相关项合并为“运行环境”
- `UpdateSettings` 和自动检查/自动下载合并为“更新”
- `About` 独立保持轻量
- `Developer` 单独放在最后，仅 dev mode 显示

### Providers 的位置

`AI Providers` 不放进 `Settings`。

证据：

- 当前真实实现里 `ProvidersSettings` 挂在 `Models` 工作台，而不是设置页
- Provider 配置属于模型工作流，不属于系统偏好

因此设置页只需要在必要时提供跳转，而不应该复制一套 provider 管理入口。

### 对齐 `QClaw` 的证据

- `QClaw` 的设置入口在聊天侧栏底部齿轮按钮
- 打开后是固定尺寸面板，不是独立长页面
- 左侧菜单 + 右侧内容，右侧主要由 `card + row` 组成
- 常见 row 语法是左侧“标题 + 说明”，右侧“开关 / 动作 / 值”

`XClaw` 不需要照搬它的弹层形态，但要吸收这套信息组织方式。

## 第二阶段方向

第一阶段只改结构和层级。第二阶段再继续收：

- Gateway proxy / doctor / telemetry 的次级视觉语言
- 设置页内部按钮、badge、日志块的一致性
- 与 `Models` 工作台之间的跳转关系

## 不做

- 不把设置页改成多层嵌套路由
- 不做全局搜索
- 不抄 `QClaw` 的像素布局
- 不把开发者工具默认前置到普通用户视线中心
