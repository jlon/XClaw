# 聊天侧栏控制问题记录

## 1. 入口层级最初挂错了

前一版把两个按钮默认挂在了聊天工具栏右侧。

这会导致：

- 视觉位置落在窗口右上，而不是左侧会话区对应的顶栏带
- 和搜索框、会话列表的关系被打散
- 用户看到的体验与 QClaw 截图心智不一致

处理：

- 把这组按钮提升到 `TitleBar`
- 在标题栏内部为聊天侧栏预留固定宽度区域，让按钮落在左侧顶栏带
- `ChatToolbar` 退回只负责刷新、thinking、runtime

## 2. 之前用的是近似图标，不是真图形

前一版使用了 Lucide 的 `PanelLeftOpen/Close` 和 `MessageCirclePlus`。

功能上能用，但图形不是 QClaw 那套。

处理：

- 直接抄 QClaw 的 SVG 路径
- 用 `currentColor` 承接主题色，避免再维护黑白两套图片切换逻辑

## 3. 新建会话不能退化

原有新建会话支持多 Agent 选择。

如果只是把按钮移到顶栏，但实现成固定 `/new` 跳转，会比旧能力更弱。

处理：

- 继续保留多 Agent 选择菜单
- 单 Agent 才直接进入 `/new`

## 4. 会话重名仍然需要可访问性区分

聊天列表里多个同名会话会让自动化测试和辅助功能拿到重复名称。

处理：

- 同名时在可访问名称追加 Agent 后缀

## 5. 标题栏按钮最初使用了错误的盒模型

前一版虽然把控件挪进了标题栏，但仍然沿用了通用 `Button`：

- 按钮本身带字号、padding 和圆角语义
- 容器没有吃满标题栏高度
- inline SVG 仍按文本基线参与排版

结果就是：

- 两个图标视觉上偏上
- 新建会话图标和收起按钮不在同一条水平线上
- 和 QClaw 的裸 icon action 质感不一致

处理：

- 标题栏插槽改为整高承载
- 控件改成裸 `button`
- 图标统一 `24px` 且 `display:block`
- 收起态取消固定宽度，让控件自动左对齐到标题栏左侧安全区

## 6. 工作台和聊天页最初并没有真正公用一个入口

前一版只是让两个地方用了同一枚图标和近似 class：

- 聊天页按钮在 `TitleBar`
- 工作台按钮还留在 `Sidebar` 内部
- 两者不是同一个挂载层，也不是同一个组件来源

这会导致：

- 用户感知成两套入口
- 工作台页仍然有一个“侧栏里再嵌一颗收起按钮”的网页式结构
- 后续微调时两边很容易再次跑偏

处理：

- 把工作台的收起按钮从 `Sidebar` 顶部移除
- 非聊天页的 `TitleBar` 接入同一颗共享按钮
- 聊天页和工作台页都从共享组件取同一枚切换控件

## 7. 共享控件不等于共享布局

前一版把工作台的收缩按钮也挂进了 `TitleBar`，但直接复用了聊天页之外的默认左侧插槽宽度。

在 macOS 上这会撞上原生 traffic lights：

- 聊天页收起态有自己的安全区偏移
- 工作台收起态如果仍用 `w-11 justify-center`，按钮会落进交通灯覆盖区

处理：

- 保留共享按钮组件
- 但 mac 工作台收起态单独使用标题栏安全区偏移
- Windows 继续保留原来的窄 rail 对齐方式
