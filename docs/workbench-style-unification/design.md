# 工作台风格统一设计

## 背景

`模型 / 智能体 / 频道 / 技能 / 定时任务` 五个工作台已经共享了一套主题 token，但“桌面工作台质感”还没有被写成统一合同，导致实现不断在两个错误之间摆动：

- 一种错误是把去网页感理解成“去层级”，结果界面发白、发虚、发平；
- 另一种错误是把桌面感理解成“多卡片、多说明、多入口”，结果又长回后台控制台。

`QClaw` 的价值不在于它的具体颜色值，而在于它证明了一件事：  
**桌面工作台的舒服感来自稳定的 substrate、清晰的层级、克制的 utility 语法，而不是营销式 hero 或大面积品牌铺色。**

`XClaw` 这轮继续遵守主线：

> **QClaw substrate, XClaw accent**

但这条原则必须落成可执行的工作台合同，而不是停留在口号。

## 目标

- 明确“桌面工作台质感”到底由哪些结构和密度构成
- 为五个工作台提供统一的布局与 surface 规则
- 以 `技能` 页当前较成熟的桌面 pane 节奏作为本地参考
- 让 `智能体`、`频道`、`模型` 等页面的浏览区和 detail pane 回到同一种桌面语法
- 禁止继续回到网页 hero、后台摘要墙、营销卡片或 dashboard 叠层
- 保持 mac / Windows 共用一套设计语言，只做极轻的平台细节适配

## 核心判断

### 1. 桌面工作台不是“页面美化”

桌面工作台首先是**任务流容器**，其次才是视觉皮肤。

它必须先回答：

- 用户现在是在浏览、选择，还是在编辑、安装、绑定？
- 当前主任务只有一个，还是被四五个二级动作打断？
- 当前层看到的信息，是为了决策，还是只是重复说明？

如果这些关系不清楚，再好的配色也只会做成“更漂亮的网页后台”。

### 2. 桌面工作台不是“越素越高级”

之前的实现已经证明：

- 只压淡颜色，不会更高级；
- 只减少阴影，不会更桌面；
- 只减少文字，不会更清晰。

真正的桌面质感来自：

- 清楚的层级
- 明确的边界
- 精准的留白
- 稳定的对比
- 一套一致的 utility grammar

### 3. 本地参考页是 `技能`

在 `XClaw` 现有页面里，`技能` 页的某些特征是正确的：

- 顶部是单层工具头，不是 hero
- 搜索、筛选、主动作共享同一条工具带
- 卡片的密度和留白更接近桌面 pane，而不是运营卡片
- 详情/弹层的 utility 语法更稳定

因此：

- `QClaw` 负责提供 substrate 与桌面纪律
- `技能` 页负责提供本地可复用的 pane 密度和工具带语法

## 桌面工作台质感合同

下面 7 条是硬规则，不再允许凭感觉漂移。

### 1. 一页只允许一个主任务心智

每个工作台必须只有一个主任务流。

例如：

- `智能体 / 本地`：选择智能体 -> 进入右侧工作区
- `智能体 / 市场`：浏览模板 -> 查看详情 -> 安装
- `频道`：选择频道/账号 -> 在右侧编辑
- `技能`：浏览技能 -> 管理详情/安装

禁止在同一层同时承担：

- 浏览
- 解释
- 编辑
- 来源核对
- 高危管理

一旦同层同时承担五件事，页面就会重新长回后台。

### 2. 浏览区与 detail pane 只能有两层主 surface

工作台主区只允许两层主 surface：

- 浏览/导航 pane
- detail workbench

局部信息可以存在轻事实卡，但不允许出现：

- “卡片里面套摘要壳，再套事实卡”
- “hero 里再塞大面板”
- “detail pane 里再长出第二个后台摘要板”

### 3. 工具带必须是一条完整语法

搜索、分段切换、筛选、刷新、主动作必须共享一条工具语法：

- 同一高度预算
- 同一圆角预算
- 同一 hover/active 强度
- 同一边界和阴影密度

不允许出现：

- 搜索像网页表单
- 分段切换像标签页
- 主按钮像营销 CTA
- 次按钮像后台 ghost button

### 4. 先减字，再补图标

图标不是装饰，只是扫描辅助。

执行顺序必须是：

1. 删除重复说明
2. 压缩重复事实
3. 再用轻图标帮助识别

禁止反过来：

- 用更多图标掩盖更多文字
- 用 badge 替代结构
- 用说明文撑起本该由布局表达的层级

### 5. 高清感来自边界、字重和节奏

“高清”不是更亮、更花，而是：

- 默认文字回到正常字重，不滥用 `font-medium`
- 标题、说明、元信息三级对比稳定
- 边框轻但准，阴影短而稳
- 白底干净但不发虚
- 选中态清楚，但不发光

标准做法：

- 主信息靠字重与留白建立层级
- 次信息靠色值和字号后退
- 交互反馈靠 hover / selected / focus 的清晰差异

### 6. 主动作只保留一个

每个工作台只允许一个主 CTA。

例如：

- `智能体 / 本地` 的主动作是 `开始对话`
- `智能体 / 市场` 的主动作是 `安装`
- `技能` 的主动作是 `添加技能`

其余动作全部降级为：

- utility button
- 更多菜单
- 文本入口

禁止出现：

- hero 一个主按钮
- summary 再一个主按钮
- 空状态再复制第三个主按钮

### 7. 真实文件、真实运行时、真实来源分层展示

文件系统、运行时状态、来源证据都必须真实，但不能抢同一层。

例如在 `智能体` 工作台：

- 顶部只表达身份与主动作
- `人格文件` 负责内置文件编辑
- `绑定与运行` 负责频道和运行状态
- `市场详情` 负责安装与来源证据

不允许把：

- 路径
- 来源路径
- 运行时目录
- 编辑入口
- 删除入口

全部抬到第一层。

## 统一的工作台结构

### 1. 页头

页头不是 hero，也不是 bare toolbar。

统一规则：

- 左侧只放标题
- 右侧只放模式切换或主级 utility
- 页头下边距必须收紧
- 默认不再显示图标锚点
- 默认不再显示说明副标题，除非该页确实需要一行任务定义

### 2. 浏览区

浏览区负责：

- 搜索
- 筛选
- 选择
- 轻量创建入口

不负责长说明。

本地 `智能体` 的浏览区应更像：

- 选择卡
- 轻摘要
- 清晰选中态

而不是：

- 卡片套卡片
- 大统计卡
- 目录树

### 3. detail pane

detail pane 负责当前对象的主任务工作。

它应该稳定、安静、可连续使用：

- 顶部 hero 只放身份、状态、主动作
- 事实区用轻卡片，不用摘要墙
- 编辑区像编辑器，不像后台表单
- 绑定区像操作 pane，不像监控面板

### 4. 市场模式

市场不是目录树，也不是营销海报墙。

市场卡片只负责：

- 识别模板
- 传达一句话价值
- 提供轻量亮点

详情区再负责：

- 安装
- 适用场景
- 亮点
- 来源证据

## 反模式

以下都视为违约：

- 只改颜色，不改结构
- 为了“更桌面”继续加说明文字
- 为了“更精致”继续加 badge、标签、图标
- 在 hero 里塞事实卡和说明区
- 在 detail pane 里重复展示浏览区已经给出的信息
- 用后台摘要墙表达本该由布局表达的层级
- 用三套不同密度的搜索框、分段控件和按钮

## 各页面的统一方向

### 模型

- 从 billboard hero 继续压回工具页
- 强调 provider 与 usage 工作区，而不是页头存在感

### 智能体

- `本地`：单列/自适应卡片浏览区 + 右侧工作台
- `市场`：卡片浏览 + 安装详情
- `人格文件` 保持真正的编辑工作区

### 频道

- 保持 split-pane
- 页头和工具带继续统一
- 不允许再长出 dashboard 式摘要墙

### 技能

- 继续作为本地 pane 密度和工具带语法的参考页
- 不做回退式扁平化

### 定时任务

- 继续维持桌面工具页密度
- 强调执行对象和任务状态，不回到营销化头部

## 验收标准

只有同时满足下面 4 条，才算“桌面工作台质感统一”：

1. 从任一工作台切到另一页，不会觉得像切了一个产品
2. 浏览区和 detail pane 的层级稳定，没有后台摘要墙
3. 主动作、utility、搜索、切换的语法一致
4. 页面在默认窗口下也有清晰层级，不发虚、不扁平、不堆字

## 当前决定

- 继续以 `QClaw substrate, XClaw accent` 为全局基底
- 以 `技能` 页当前的 pane 节奏作为本地参考
- `智能体` 是这一轮最重要的落地页，因为它最容易从后台列表长回网页控制台
