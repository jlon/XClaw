# 工作台风格统一设计

## 背景

`模型 / 智能体 / 频道 / 技能 / 定时任务` 五个工作台已经共享了一套主题 token，但“桌面工作台质感”还没有被写成统一合同，导致实现不断在两个错误之间摆动：

- 一种错误是把去网页感理解成“去层级”，结果界面发白、发虚、发平；
- 另一种错误是把桌面感理解成“多卡片、多说明、多入口”，结果又长回后台控制台。

`QClaw` 的价值不在于它的具体颜色值，而在于它证明了一件事：  
**桌面工作台的舒服感来自稳定的 substrate、清晰的层级、克制的 utility 语法，而不是营销式 hero 或大面积品牌铺色。**

`XClaw` 这轮继续遵守主线：

> **QClaw substrate, XClaw accent**

但这条原则必须落成可执行的工作台合同，而不是停留在口号。

## 目标

- 明确“桌面工作台质感”到底由哪些结构和密度构成
- 为五个工作台提供统一的布局与 surface 规则
- 以 `技能` 页当前较成熟的桌面 pane 节奏作为本地参考
- 让 `智能体`、`频道`、`模型` 等页面的浏览区和 detail pane 回到同一种桌面语法
- 禁止继续回到网页 hero、后台摘要墙、营销卡片或 dashboard 叠层
- 保持 mac / Windows 共用一套设计语言，只做极轻的平台细节适配

## 核心判断

### 1. 桌面工作台不是“页面美化”

桌面工作台首先是**任务流容器**，其次才是视觉皮肤。

它必须先回答：

- 用户现在是在浏览、选择，还是在编辑、安装、绑定？
- 当前主任务只有一个，还是被四五个二级动作打断？
- 当前层看到的信息，是为了决策，还是只是重复说明？

如果这些关系不清楚，再好的配色也只会做成“更漂亮的网页后台”。

### 2. 桌面工作台不是“越素越高级”

之前的实现已经证明：

- 只压淡颜色，不会更高级；
- 只减少阴影，不会更桌面；
- 只减少文字，不会更清晰。

真正的桌面质感来自：

- 清楚的层级
- 明确的边界
- 精准的留白
- 稳定的对比
- 一套一致的 utility grammar

### 3. 本地参考页是 `技能`

在 `XClaw` 现有页面里，`技能` 页的某些特征是正确的：

- 顶部是单层工具头，不是 hero
- 搜索、筛选、主动作共享同一条工具带
- 卡片的密度和留白更接近桌面 pane，而不是运营卡片
- 详情/弹层的 utility 语法更稳定

因此：

- `QClaw` 负责提供 substrate 与桌面纪律
- `技能` 页负责提供本地可复用的 pane 密度和工具带语法

## 桌面工作台质感合同

下面 7 条不再是“设计建议”，而是必须编号执行的铁律。  
后续文档、测试、review 和实现都统一用 `WU-01` 到 `WU-07` 引用，不再用模糊描述代替。

### WU-01 一页只允许一个主任务心智

每个工作台必须只有一个主任务流。

例如：

- `智能体 / 本地`：选择智能体 -> 进入右侧工作区
- `智能体 / 市场`：浏览模板 -> 查看详情 -> 安装
- `频道`：选择频道/账号 -> 在右侧编辑
- `技能`：浏览技能 -> 管理详情/安装

禁止在同一层同时承担：

- 浏览
- 解释
- 编辑
- 来源核对
- 高危管理

一旦同层同时承担五件事，页面就会重新长回后台。

#### 可执行定义

- 作用域按“页面的当前 mode”计算，不按整页混算  
- 一个 mode 只能有一条黄金路径：`进入 -> 选择/浏览 -> 执行主任务 -> 完成`
- 同一 mode 的首屏不得同时出现两个等权重主任务

### WU-02 浏览区与 detail pane 只能有两层主 surface

工作台主区只允许两层主 surface：

- 浏览/导航 pane
- detail workbench

局部信息可以存在轻事实卡，但不允许出现：

- “卡片里面套摘要壳，再套事实卡”
- “hero 里再塞大面板”
- “detail pane 里再长出第二个后台摘要板”

#### 可执行定义

- 首屏只允许 `页头 / 工具带 / 浏览 pane / detail pane` 四块主层
- detail pane 首屏只允许 `身份区 + 一个主工作区 + 一个状态/事实条`
- 凡是再出现“摘要壳 + 事实卡 + 次级摘要壳”的，都判定为违约

### WU-03 工具带必须是一条完整语法

搜索、分段切换、筛选、刷新、主动作必须共享一条工具语法：

- 同一高度预算
- 同一圆角预算
- 同一 hover/active 强度
- 同一边界和阴影密度

不允许出现：

- 搜索像网页表单
- 分段切换像标签页
- 主按钮像营销 CTA
- 次按钮像后台 ghost button

#### 可执行定义

- 主工具带白名单仅包含：`模式切换 / 搜索 / 筛选 / 刷新 / 主 CTA`
- 顺序固定为：`模式切换(若有) -> 搜索/筛选 -> 次级 utility -> 主 CTA`
- 高度预算只允许进入 `36 / 40 / 44` 三档；新增第四档视为违约
- 默认工作台工具带优先使用 `36px`
- `40px+` 只允许出现在表单、模态和强编辑场景，不允许回流到页级工具带
- 搜索、segmented、刷新、次级按钮必须维持同一圆角带宽，不允许混用 `pill / sharp / chip`

### WU-04 先减字，再补图标

图标不是装饰，只是扫描辅助。

执行顺序必须是：

1. 删除重复说明
2. 压缩重复事实
3. 再用轻图标帮助识别

禁止反过来：

- 用更多图标掩盖更多文字
- 用 badge 替代结构
- 用说明文撑起本该由布局表达的层级

#### 可执行定义

- 页头默认最多：`标题 + 1 行任务定义`
- 浏览项默认最多：`标题 + 1 行元信息`
- detail 首屏不得重复浏览区已经表达过的身份事实
- badge 只能做状态补充，不能承担主信息表达

### WU-05 高清感来自边界、字重和节奏

“高清”不是更亮、更花，而是：

- 默认文字回到正常字重，不滥用 `font-medium`
- 标题、说明、元信息三级对比稳定
- 边框轻但准，阴影短而稳
- 白底干净但不发虚
- 选中态清楚，但不发光

标准做法：

- 主信息靠字重与留白建立层级
- 次信息靠色值和字号后退
- 交互反馈靠 hover / selected / focus 的清晰差异

#### 可执行定义

- 主信息默认字重回到常规或 semibold，禁止用连续 `font-medium` 堆层级
- 选中态只能靠边界、背景和阴影轻差异建立，不允许发光色块
- 白底必须通过边界和分层建立清晰度，不能靠大面积空白冒充高级
- substrate 固定为四层：`window chrome / workspace substrate / pane surface / field-or-selected-row`
- 四层必须存在稳定对比，不允许整页同白度、同边框、同阴影

### WU-06 主动作只保留一个

每个工作台只允许一个主 CTA。

例如：

- `智能体 / 本地` 的主动作是 `开始对话`
- `智能体 / 市场` 的主动作是 `安装`
- `技能` 的主动作是 `添加技能`

其余动作全部降级为：

- utility button
- 更多菜单
- 文本入口

禁止出现：

- hero 一个主按钮
- summary 再一个主按钮
- 空状态再复制第三个主按钮

#### 可执行定义

- 页级主 CTA 永远只有一个
- 弹窗提交按钮不计入页级主 CTA
- 空态不得发明新的主 CTA，只能复用同一动作语义
- 危险动作不得进入首屏 hero，只能进入更多菜单或二次确认

### WU-07 真实文件、真实运行时、真实来源分层展示

文件系统、运行时状态、来源证据都必须真实，但不能抢同一层。

例如在 `智能体` 工作台：

- 顶部只表达身份与主动作
- `人格文件` 负责内置文件编辑
- `绑定与运行` 负责频道和运行状态
- `市场详情` 负责安装与来源证据

不允许把：

- 路径
- 来源路径
- 运行时目录
- 编辑入口
- 删除入口

全部抬到第一层。

#### 可执行定义

- 只有会阻断当前主任务的信息，才允许升级到第一视觉层
- `路径 / 来源路径 / 运行目录 / 删除入口` 默认只能待在二级区
- 异常态可以上浮，但必须在异常恢复后自动回退到原层级

## 模式合同

每个工作台 mode 都必须能回答下面 6 个问题；回答不完整，不允许进入实现：

- 主任务是什么
- 入口是什么
- 完成动作是什么
- 首屏允许出现哪些次级动作
- 首屏禁止出现哪些信息
- 当前 mode 的默认窗口承载方式是什么

### 智能体 / 本地

- 主任务：选择智能体并进入右侧工作区
- 完成动作：开始对话，或完成文件/绑定配置
- 允许次级动作：编辑基本信息、删除、管理频道
- 首屏禁止：路径堆叠、重复事实卡、文件管理器分支、危险动作直出
- 默认窗口 `1280x800` 下：
  - 左侧浏览区默认单列卡片
  - 右侧 detail pane 首屏必须完整露出 `identity row + 事实带 + 第一个工作区`

### 智能体 / 市场

- 主任务：浏览模板并安装
- 完成动作：安装到本地并回到工作区
- 允许次级动作：切换分类、搜索、查看来源证据
- 首屏禁止：目录路径、安装方式解释墙、重复 badge
- 默认窗口 `1280x800` 下：
  - 浏览区默认 `2` 列摘要卡
  - 单卡描述最多 `2` 行
  - badge 最多 `1` 个状态或分类，不允许 badge 墙

### 频道

- 主任务：选择频道/账号并编辑
- 完成动作：完成配置并看到真实连接状态
- 允许次级动作：刷新、筛选、状态查看
- 首屏禁止：大摘要墙、双搜索入口、营销式卡片
- 默认窗口 `1280x800` 下：
  - 页头、工具带、左侧列表和右侧编辑区必须同时可见

### 技能

- 主任务：浏览、安装、管理技能
- 完成动作：完成启用/安装/卸载
- 允许次级动作：搜索、筛选、打开详情
- 首屏禁止：大英雄头、目录树、重复说明块
- 默认窗口 `1280x800` 下：
  - 搜索、主动作、首屏卡片与详情入口必须在一屏内形成完整工作流

### 定时任务

- 主任务：浏览、创建、编辑任务
- 完成动作：任务保存并绑定真实执行智能体
- 允许次级动作：刷新、暂停/启用、查看失败
- 首屏禁止：空态重复 CTA、无智能体上下文的伪选择器
- 默认窗口 `1280x800` 下：
  - 列表首屏、状态摘要与编辑入口必须同时可见

## 默认窗口基线

桌面工作台的默认验收视口固定为：

- `1280 x 800`
- `1440 x 900`

只有这两档都通过，才允许宣称“默认窗口下成立”。  
不能继续依赖超宽屏掩盖布局问题。

## 文案预算

为防止继续长回后台说明页，统一写死：

- 页头副文案：默认 `0` 行，特殊情况下最多 `1` 行
- section 说明：默认 `0` 行，必要时最多 `1` 行
- 浏览卡：`标题 + 1 行元信息 + 0~1 行摘要`
- 市场卡：`标题 + 0~1 行 headline + 0~2 行摘要 + 1 行亮点`
- 空态：`1 个标题 + 1 行说明 + 1 个动作`

超过预算，不允许靠“更完整”作为理由保留。

## 统一的工作台结构

### 1. 页头

页头不是 hero，也不是 bare toolbar。

统一规则：

- 左侧只放标题
- 右侧只放模式切换或主级 utility
- 页头下边距必须收紧
- 默认不再显示图标锚点
- 默认不再显示说明副标题，除非该页确实需要一行任务定义

### 2. 浏览区

浏览区负责：

- 搜索
- 筛选
- 选择
- 轻量创建入口

不负责长说明。

本地 `智能体` 的浏览区应更像：

- 选择卡
- 轻摘要
- 清晰选中态

而不是：

- 卡片套卡片
- 大统计卡
- 目录树

### 3. detail pane

detail pane 负责当前对象的主任务工作。

它应该稳定、安静、可连续使用：

- 顶部 hero 只放身份、状态、主动作
- 事实区用轻卡片，不用摘要墙
- 编辑区像编辑器，不像后台表单
- 绑定区像操作 pane，不像监控面板

### 4. 市场模式

市场不是目录树，也不是营销海报墙。

市场卡片只负责：

- 识别模板
- 传达一句话价值
- 提供轻量亮点

详情区再负责：

- 安装
- 适用场景
- 亮点
- 来源证据

## 三轮复盘结论

### 第一轮：产品动线 review

- 旧版最大的问题是只有“统一设计语言”，没有“mode 合同”
- 现在已明确：所有铁律都按 mode 执行，不按整页模糊执行
- 如果某页某个 mode 无法回答主任务和完成动作，就视为没设计完

### 第二轮：视觉层级 review

- 旧版最大的问题是只强调“去网页感”，没有防“去层级”
- 现在已明确：`WU-02 / WU-05` 共同约束两层主 surface 和高清感预算
- 任何把 detail pane 做成大白板、把浏览区做成后台目录树的实现都视为回退

### 第三轮：工程验收 review

- 旧版最大的问题是“像合同”，但还不能阻断回退
- 现在已明确：所有铁律都必须能映射到自动化或手工验收编号
- 没有编号、没有证据、没有状态矩阵的项，不允许标记完成

## 反模式

以下都视为违约：

- 只改颜色，不改结构
- 为了“更桌面”继续加说明文字
- 为了“更精致”继续加 badge、标签、图标
- 在 hero 里塞事实卡和说明区
- 在 detail pane 里重复展示浏览区已经给出的信息
- 用后台摘要墙表达本该由布局表达的层级
- 用三套不同密度的搜索框、分段控件和按钮

## 各页面的统一方向

### 模型

- 从 billboard hero 继续压回工具页
- 强调 provider 与 usage 工作区，而不是页头存在感

### 智能体

- `本地`：单列/自适应卡片浏览区 + 右侧工作台
- `市场`：卡片浏览 + 安装详情
- `人格文件` 保持真正的编辑工作区

### 频道

- 保持 split-pane
- 页头和工具带继续统一
- 不允许再长出 dashboard 式摘要墙

### 技能

- 继续作为本地 pane 密度和工具带语法的参考页
- 不做回退式扁平化

### 定时任务

- 继续维持桌面工具页密度
- 强调执行对象和任务状态，不回到营销化头部

## 验收标准

只有同时满足下面 4 条，才算“桌面工作台质感统一”：

1. 从任一工作台切到另一页，不会觉得像切了一个产品
2. 浏览区和 detail pane 的层级稳定，没有后台摘要墙
3. 主动作、utility、搜索、切换的语法一致
4. 页面在默认窗口下也有清晰层级，不发虚、不扁平、不堆字

## 当前决定

- 继续以 `QClaw substrate, XClaw accent` 为全局基底
- 以 `技能` 页当前的 pane 节奏作为本地参考
- `智能体` 是这一轮最重要的落地页，因为它最容易从后台列表长回网页控制台
