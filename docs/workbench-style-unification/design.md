# 工作台风格统一设计

## 背景

当前 `模型 / 智能体 / 频道 / 技能 / 定时任务` 五个工作台页面虽然已经接入同一套全局主题 token，但它们的“头部语法”和“工作台节奏”并不统一：

- `模型` 仍偏大幅 hero，标题和副标题过重
- `智能体` 头部过轻，只有标题，没有完整说明层
- `频道` 头部更像工具栏标题，和其他页不是同一语言
- `技能`、`定时任务` 虽然接近，但动作区、摘要区和卡片节奏仍各走一套
- 图标底盘、头部留白、按钮高度、动效预算不一致

这说明问题已经不是颜色，而是信息架构和交互语法没有统一。

本轮不单独发明新风格，必须严格挂在 [`global-theme-refresh`](../global-theme-refresh/design.md) 的主线上执行：

> **QClaw substrate, XClaw accent**

也就是说：

- 先统一桌面工作台的结构语言
- 再在统一结构内保留 `XClaw` 的低饱和品牌点缀
- 禁止把工作台再次做成网页 hero、营销页或 dashboard

## 目标

- 将五个工作台统一到同一套桌面级 `Workbench Header Grammar`
- 保留页面间的信息密度差异，但消除“有的像 hero，有的像 toolbar”的断裂感
- 统一图标底盘、标题区、动作区、摘要区、动效预算
- 通过减少解释性文字和压缩重复说明，降低页头臃肿感
- 用少量轻图标替代部分冗余文字，让信息更像桌面状态条而不是网页说明栏
- 让 `工作台` 导航中的五个入口看起来属于同一个应用系统
- 兼容 `macOS / Windows`，不依赖平台特供皮肤
- 明确“单页单主 CTA”规则，避免页头、空态、正文重复出现多个等权重创建入口

## 非目标

- 不把五个页面做成完全一样的模板页
- 不把 `聊天 / 设置` 直接并入这一轮统一范围
- 不重做各页主体业务结构
- 不增加新的品牌色层级
- 不引入网页式大 hero、卡片 marketing、漂浮动效

## 现状诊断

### 结构差异

- `模型`
  - 使用独立的 `ModelsWorkbenchHeader`
  - 标题尺寸远大于其他页
  - 更像 billboard / hero
- `智能体`
  - 头部只有主标题和 mode switch
  - 缺少副标题与图标锚点
- `频道`
  - 标题和副标题尺寸明显偏小
  - 更像 list pane 顶部工具栏
- `技能`
  - 已具备完整标题、副标题、搜索、主动作
  - 但头部留白和动作高度与其他页不一致
- `定时任务`
  - 接近 `技能`
  - 但统计条、头部间距、按钮节奏仍是单页风格

### 视觉差异

- 图标底盘有的存在，有的不存在
- 标题字号跨越过大
- 动作按钮高度出现 `36 / 40 / 44` 混用
- 有的页面 summary 太重，有的没有 summary
- hover/active 和 loading 动效强度不一致

## 总体方案

采用统一的 **Workbench Header Grammar**，而不是统一一块皮。

意思是：

- 所有工作台都共享同一套头部结构和控件比例
- 各页只在“内容负载”上有差异，不在“设计语言”上分裂
- 页面主体布局可以不同，但页头语法必须统一

## 三轮自审结论

### 第一轮：防止“过度统一”

原始方案的问题是只强调“统一”，没有明确“统一到哪一层”。如果直接照这个 spec 实现，最容易出现的错误是：

- 把五个页面都做成同一张模板
- 为了统一头部，把 `频道` 这种 split-pane 工作台做重
- 为了统一密度，把 `模型` 的信息层次做薄

因此本轮统一的边界必须明确写死：

- **统一页头 grammar，不统一主体业务布局**
- `模型` 的图表、KPI、provider board 不进入统一范围
- `频道` 的三栏结构不进入统一范围
- `智能体` 的双栏/市场模式不进入统一范围
- `技能` 的搜索和卡片中心继续保留
- `定时任务` 的任务列表和编辑弹窗继续保留

换句话说，本特性只处理 **工作台页头、摘要和动作语法**，不处理主体工作区重排。

### 第二轮：防止“说统一，做分叉”

如果只写设计描述，不写组件边界，最后很可能还是五个页面各自手写一套“差不多”的头部。那不叫统一，只叫同步复制。

因此实现必须落到共享 primitive，而不是页面各修各的：

- `WorkbenchHeader`
- `WorkbenchHeaderIcon`
- `WorkbenchHeaderTitleBlock`
- `WorkbenchHeaderActions`
- `WorkbenchSummaryStrip`

允许页面传入不同内容，但不允许每页重新发明：

- 不同的标题字号系统
- 不同的头部 padding
- 不同的按钮高度
- 不同的图标底盘尺寸
- 不同的 summary 容器

### 第三轮：防止“统一后还是网页感”

即使结构统一，如果动效、图标底盘和搜索/动作关系不受控，页面仍会重新长回网页感。

因此还要补三条硬约束：

- 搜索框如果存在，视为 `Header Utility Field`，属于页头的一部分，但视觉权重低于标题和主按钮
- 图标底盘必须继续使用低饱和 tone，不允许把品牌色抬成大面积背景
- 页头内不允许出现任何页面独有动画，所有工作台只复用同一套 motion token

### 第四轮：防止“统一后仍然臃肿”

用户提出的方向是正确的，但必须收住边界：

- **减字是主刀，图标只是辅助**
- 如果只是继续加图标，不减少说明文字，结果只会更像网页和 dashboard

因此本轮还要增加两条硬约束：

- 页头说明文字必须先压缩，再决定是否补图标
- 图标只允许用于状态、计数、动作和唯一锚点，不允许成为装饰

### 第五轮：防止“主 CTA 泛滥”和“假目标选择”

补充两条之前没有写硬的约束：

- **单页单主 CTA**
  - 同一视口内只允许一个主按钮承担核心创建动作
  - 空态只能复用页头主动作的语义，不得复制第二个等权重主按钮
  - 如果正文必须保留入口，它只能降级为次按钮或文本入口
- **定时任务的目标智能体必须是真绑定**
  - “新建定时任务时指定哪个智能体执行”这个产品判断是正确的
  - 但这不是前端表单问题，而是端到端创建链问题
  - 如果 host / gateway 没有透传目标智能体，前端不允许先做一个假下拉框冒充支持
  - 当前版本若只能固定发给默认智能体，界面必须如实表达；若要支持多智能体，必须补齐创建链

## 实施边界

本轮实现边界固定为：

- 页头结构
- 图标底盘
- 标题/副标题
- 动作区
- summary strip
- 搜索作为 header utility 的布局关系

不进入本轮的：

- 页面主体的卡片、图表、三栏结构重排
- 模态内容重构
- 数据流和业务逻辑调整
- 页面级营销化插画或品牌视觉增强

## 统一语法

### 1. 头部结构

所有工作台页头统一为三层：

1. `Icon Anchor`
2. `Title Block`
3. `Action Rail`

可选第四层：

4. `Summary Strip`

头部基础排列：

- 左侧：图标底盘 + 标题区
- 右侧：操作按钮区
- 下方：轻摘要或筛选状态

禁止出现：

- 巨型 hero 头图
- 第二套页头
- 头部内部再嵌一层 dashboard 卡
- 标题和搜索栏各自漂浮为两层视觉中心

头部基础尺寸预算统一为：

- 上边距：跟随 `WorkspacePageShell`，页头自身不再各自追加夸张 top gap
- 标题区和动作区主行：`min-height 44px`
- 主行与 summary strip 间距：`10-12px`
- 页头与正文主工作区间距：`18-24px`

### 2. 图标底盘

统一规则：

- 尺寸：`44 x 44`
- 圆角：`14px`
- 仅图标底盘带低饱和色
- 图标本身 `18-20px`
- 图标底盘使用统一的 soft capsule / pane 语言

色系统一沿用当前工作台导航已经建立的低饱和 tone：

- `模型`：蓝灰
- `智能体`：珊瑚
- `频道`：青绿
- `技能`：琥珀
- `定时任务`：紫灰

要求：

- 只染图标底盘，不染标题文字
- 颜色只承担识别，不承担主视觉

图标底盘的实现必须来自共享 token / class，不允许每页手写颜色值。

### 3. 标题区

统一规则：

- 标题字号：`26-28px`
- 字重：`600`
- 行高紧凑，强调桌面产品而非网页标题
- 副标题字号：`13-14px`
- 副标题默认只保留一行，最多不超过一行半
- 标题区整体宽度受控，不允许大段说明挤占工作区
- 标题、副标题与图标底盘必须垂直居中到同一锚点，不允许图标独立悬浮

文案约束：

- 标题负责定义“这是哪个工作台”
- 副标题只允许解释“它主要做什么”
- 不允许在副标题里再重复主标题的语义
- 不允许出现营销式、说明书式长句
- 如果副标题删掉后页面仍然成立，应优先删除而不是保留

明确纠偏：

- `模型` 从当前超大 hero 降级到标准工作台标题
- `智能体` 补齐副标题
- `频道` 从工具栏级标题升级到标准工作台标题

### 4. 动作区

统一动作分级：

- 主按钮：`40px`
- 次按钮：`36px`
- 图标按钮：`36px`

规则：

- 每页最多一个主按钮
- 同一视口只允许一个主 CTA
- 刷新类动作必须使用次按钮或图标按钮
- 搜索框不属于动作按钮，不应和主按钮在视觉权重上相同
- 右侧动作区默认只是一行，不再长成网页 toolbar 群

补充规则：

- 搜索存在时，优先占据左侧 utility 位，不与主按钮抢右侧主导位
- 当窗口宽度不足时，搜索和动作区允许折到第二行，但顺序不变：
- 标题区优先
- 搜索/utility 次之
- 主按钮最后保留
- 不允许页面自己决定一会儿“搜索在标题下”，一会儿“搜索在最右侧”
- 如果页面已经在页头暴露主创建动作，正文空态不得再重复渲染第二个创建类主按钮

轻图标约束：

- 刷新、筛选、更多、状态切换这类高频动作优先图标化
- 图标按钮只承担工具语义，不承担主视觉
- 不允许为“看起来更丰富”给普通说明文字补装饰 icon

### 5. 摘要区

摘要区存在，但降级成轻量 summary strip，不再成为第二个页头。

统一规则：

- 字号：`11.5-12px`
- 仅用于数量、状态、筛选摘要
- 不承载解释型文案
- 只允许一行轻信息，必要时自动换行
- 优先采用 `轻图标 + 数字 + 极短标签` 的桌面状态条语法，而不是完整句子

摘要区图标规则：

- 只允许使用中性或低饱和小图标
- 图标尺寸控制在 `12-14px`
- 每个摘要单元只保留一个图标
- 图标只用于帮助扫描，不允许形成第二排视觉焦点

适用：

- `技能`：总数 / 已启用 / 内置数量
- `定时任务`：总数 / 启用 / 暂停 / 失败
- `频道`：可用状态不放在头部 summary，继续留在工作区告警带
- `智能体`、`模型`：如无必要可不显示 summary

## 动效统一

本轮不追求更多动画，只追求同一预算。

统一预算：

- hover 提升：最多 `1px`
- hover / active / border / bg 过渡：`140-180ms`
- loading：只允许 `spin`
- 状态点呼吸：仅限弱提示场景
- 禁止页头范围内单独定义新的 `ease / duration / keyframes`

禁止：

- 页头独立浮动
- 标题弹跳
- 图标缩放表演
- 页面级 stagger reveal
- 某个工作台单独拥有更重的 hover 阴影

## 页级落点

### 模型

调整方向：

- 保留当前信息丰富度
- 但头部从 billboard 降到标准工作台 grammar
- KPI、图表和 provider 选择仍留在正文区
- 头部只负责“当前工作台是什么 + 可以做什么”
- 不再允许独立的超大标题组件脱离统一 primitive

### 智能体

调整方向：

- 增加图标底盘和副标题
- mode switch 保留在右侧动作区
- 不再只剩一个裸标题

### 频道

调整方向：

- 提升头部存在感，但不增加重量
- 保持它作为 split-pane workbench 的工具属性
- 刷新按钮继续保留，但用统一次按钮语法

### 技能

调整方向：

- 保留搜索和添加技能
- 把头部 spacing、图标底盘、summary strip 收到标准 grammar
- 不再让搜索框和标题各自抢主视觉
- 搜索框明确归入 header utility，不再作为第二个 hero 区块
- 头部默认文案应进一步压缩，避免页面一打开就先读说明

### 定时任务

调整方向：

- 保留新增任务主按钮
- 新建任务必须显式指定“由哪个智能体执行”
- 将统计条降级为统一 summary strip
- 头部间距、按钮和说明文案全部向统一 grammar 靠
- 统计优先图标化，减少“总数 / 启用 / 暂停 / 失败”的重复文字负担
- 在端到端支持补齐之前，不能用纯前端状态伪装“已支持多智能体定时任务”

补充约束：

- `TaskDialog` 最终必须包含目标智能体选择，而不是默认隐式绑定
- 目标智能体必须进入 host / gateway 创建链
- 如果 `sessionTarget="main"`，只能用于默认智能体；非默认智能体必须走 `agentTurn + isolated/current/session:*` 的真实 OpenClaw 语义

## 与全局主题的关系

本特性不是独立主题，而是 `global-theme-refresh` 在工作台层的继续落地。

必须遵守：

- 基底继续使用冷中性 desktop substrate
- 不新增第二套 panel 语言
- 不因为统一而引入更热的品牌背景
- 不让单页重新长回网页 hero 或 dashboard card

如果某个工作台为了“更有特色”而破坏以上规则，应视为回归。

## 实现约束

实现时必须优先复用或新建共享组件，不接受以下做法：

- 只复制 class 到五个页面
- 在每页单独维护一份页头 spacing
- 在每页单独定义按钮高度和图标底盘尺寸
- 在 `ModelsWorkbenchHeader`、`Skills` 页头、`Cron` 页头里继续维护三套平行语法

允许保留页级包装，但页头核心 primitive 必须收编到共享层。

## 信息压缩原则

本轮统一的一个附加目标是：**减少臃肿，而不是增加装饰。**

执行顺序必须固定：

1. 先删除重复说明
2. 再缩短保留文案
3. 最后才用少量轻图标补扫描效率

禁止倒过来做：

- 先加图标，再想办法解释为什么文字还这么多
- 把图标当成“更精致”的装饰层
- 因为怕空而补第二行说明

判断标准：

- 如果用户在工作台切换时首先看到的是文字解释，说明还不够克制
- 如果用户首先看到的是一排图标，说明又做过头了
- 正确状态应该是：先识别图标锚点和标题，再用一眼扫过的 summary 理解状态

## 验收标准

当用户从左侧 `工作台` 在五个入口之间切换时，应明确感受到：

- 它们属于同一套桌面工作台系统
- 不是五个不同团队做的页面
- 每页结构相似，但不会死板雷同
- 图标、标题、按钮、摘要、动效的语言一致
- 不会出现某页过重、某页过轻、某页像 hero、某页像后台表格的断裂感

## 实施原则

- 先统一头部 grammar，再做局部细节
- 优先移除结构级差异，不先调颜色
- 不对主体业务布局做无关重构
- 所有实现都必须建立在现有 `WorkspacePage*` 框架之上
- 任何实现完成前，都必须回看 `global-theme-refresh`，确认没有把桌面质感重新做成网页感
