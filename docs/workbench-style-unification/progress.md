## 三轮 review 结论

- 第一轮：产品动线 review
  - 旧版最大问题是只有统一方向，没有 mode 合同
  - 现在已明确：按 mode 定义主任务、完成动作、禁止上屏信息
- 第二轮：视觉层级 review
  - 旧版最大问题是只强调去网页感，没有防去层级
  - 现在已明确：两层主 surface、高清感预算、禁止大白板和后台摘要墙
- 第三轮：工程验收 review
  - 旧版最大问题是像宣言，不像合同
  - 现在已明确：规则必须编号、状态必须覆盖、完成必须带证据
- 第四轮：默认窗口与滚动纪律 review
  - 旧版最大问题是没有把“内部滚动条不能成为默认布局解法”写死
  - 现在已明确：默认基线视口下，主 pane / 主模态不得依赖内部滚动条完成主任务

## 当前结论

- 工作台统一的核心不是“共享标题组件”，而是：
  - 共享 surface 层级
  - 共享工具带 grammar
  - 共享浏览区 / detail pane 的密度纪律
  - 共享内容宽度轨道和默认视口下的无滚动模态纪律
- 过去的错误不是“没学 QClaw”，而是：
  - 把去网页感误解成去层级
  - 把桌面感误解成大卡片或大白板
- `/models` 已确认还需要专项铁律，不然实现会在三个方向反复摇摆：
  - Provider Board 长回“浏览 + docs + footer 操作”
  - 默认态分析区和 Provider Board 首屏等权
  - 图标和 breakdown 重新滑回伪彩色与报表语法
- 默认窗口的滚动纪律也已补齐，否则很多页面都会用“给模态加滚动条”伪装成完成
- `定时任务` 现在不再允许创建“没有投递意义”的任务：
  - 只能选择当前智能体已绑定的频道账号
  - 必须补齐目标会话 ID
  - Host API 和 IPC 分支的 delivery contract 已收平，不再一条有 target、一条偷偷写 `delivery:none`
- 目前最成熟的本地参考是 `技能` 页：
  - 搜索、筛选、主动作在一条工具带
  - 卡片密度稳定
  - detail/弹层更像桌面 pane，而不是网页设置卡
- `频道` 页已经从“网页搜索横幅 + 重摘要 + 橙色 CTA 卡片”收回到桌面工具带和行级动作语法
- `定时任务` 创建/编辑模态已纠正“左大右小”的错误轨道，改成“上部双栏基础信息 + 下部全宽调度”，并允许内部滚动但隐藏滚动条。
- `智能体` 工作台是当前最关键的落地页：
  - 既有本地资源浏览
  - 又有 detail workbench
  - 又有市场安装
  - 最容易暴露“后台感”和“层级混乱”
- `智能体` 右侧当前规则已经明确：
  - hero 只放身份与主动作
  - `人格文件` 只展示内置文件，并走弹窗编辑
  - `绑定与运行` 不再重复铺运行时事实卡
- 工作台动画这轮继续只做“统一语法”，不做“更多动效”：
  - 侧边栏、工具带、资源卡、列表行都接回共享 motion grammar
  - hover 位移统一收成 `motion-safe:hover:-translate-y-[1px]`
  - `prefers-reduced-motion` 下不再允许偷偷上浮
- 后续任何工作台实现如果无法映射到 `WU-01` 到 `WU-08`，一律视为未完成
