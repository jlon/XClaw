## 三轮 review 结论

- 第一轮：产品动线 review
  - 旧版最大问题是只有统一方向，没有 mode 合同
  - 现在已明确：按 mode 定义主任务、完成动作、禁止上屏信息
- 第二轮：视觉层级 review
  - 旧版最大问题是只强调去网页感，没有防去层级
  - 现在已明确：两层主 surface、高清感预算、禁止大白板和后台摘要墙
- 第三轮：工程验收 review
  - 旧版最大问题是像宣言，不像合同
  - 现在已明确：规则必须编号、状态必须覆盖、完成必须带证据

## 铁律状态

当前这份合同只有满足下面 3 条，才算“真正形成铁律”：

- `progress / testing` 已能要求证据，而不是只收口号

## 当前结论

- 工作台统一的核心不是“共享标题组件”，而是：
  - 共享 surface 层级
  - 共享工具带 grammar
  - 共享浏览区 / detail pane 的密度纪律
- 过去的错误不是“没学 QClaw”，而是：
  - 把去网页感误解成去层级
  - 把桌面感误解成大卡片或大白板
- 目前最成熟的本地参考是 `技能` 页：
  - 搜索、筛选、主动作在一条工具带
  - 卡片密度稳定
  - detail/弹层更像桌面 pane，而不是网页设置卡
- `频道` 页已经从“网页搜索横幅 + 重摘要 + 橙色 CTA 卡片”收回到桌面工具带和行级动作语法
- `智能体` 工作台是当前最关键的落地页：
  - 既有本地资源浏览
  - 又有 detail workbench
  - 又有市场安装
  - 最容易暴露“后台感”和“层级混乱”
- `智能体` 右侧当前规则已经明确：
  - hero 只放身份与主动作
  - `人格文件` 只展示内置文件，并走弹窗编辑
  - `绑定与运行` 不再重复铺运行时事实卡
- 后续任何工作台实现如果无法映射到 `WU-01` 到 `WU-07`，一律视为未完成
