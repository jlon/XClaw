# 工作台风格统一问题记录

## 当前已确认问题

### 1. 头部语法分裂

- `模型` 过重
- `频道` 过轻
- `智能体` 信息层不足
- `技能 / 定时任务` 自成一套

### 2. 图标底盘不统一

- 不是每个工作台都有统一的 icon anchor
- 颜色虽然已建立低饱和 tone，但还没有落实为统一组件语法

### 3. 动作区分级不统一

- 刷新、主动作、图标按钮高度和体量混用
- 某些工作台动作区更像网页 toolbar

### 4. 摘要区语义不统一

- 有的页面完全没有
- 有的页面过重
- 有的页面把状态告警和 summary 混在一起

### 5. 原 spec 存在过度统一风险

- 如果不写清边界，后续实现容易把五页做成同一张模板
- 这会伤害 `频道 / 模型 / 智能体` 的真实工作区效率

### 6. 原 spec 缺共享组件边界

- 如果没有 `WorkbenchHeader` 级 primitive，最后大概率仍会是五页各自实现“相似头部”
- 这会导致后续维护继续分叉

### 7. 原 spec 对搜索与动作区关系定义不够清楚

- `技能` 这类带搜索的工作台最容易重新长回网页 hero
- 需要明确搜索是 header utility，不是第二个视觉主角

### 8. 原 spec 对“减少臃肿”的约束不够硬

- 如果不明确“减字优先”，实现时很容易继续保留长副标题
- 如果不明确图标边界，轻图标会演变成装饰化堆砌

### 9. 原 spec 没有明确“单页单主 CTA”

- `定时任务` 首轮迁移时就暴露了这个问题：页头已经有主创建动作，空态里又重复渲染了一颗主按钮
- 如果不把这条规则写硬，后续 `技能 / 智能体 / 模型` 也会继续出现相同问题

### 10. `定时任务` 创建链丢失了目标智能体

- OpenClaw 底层 `cron.add` 真正支持 `agentId`
- XClaw 当前类型层和 host route 没有把 `agentId` 透传到创建链
- 这意味着当前 UI 里的“新建任务”仍然是隐式默认目标，而不是显式指定执行智能体
- 在补齐 host / gateway 透传前，不能只加前端选择器做假支持

## 待确认问题

### 1. `模型` 页是否保留现有头部组件

倾向：

- 保留组件
- 但将其收编到统一 grammar，而不是继续维持独立 hero

### 2. `频道` 页是否需要图标底盘

倾向：

- 需要
- 但只放在页头，不进入三栏主体

### 3. `智能体` 页副标题文案

需要在实现前确认是否直接复用现有国际化资源，或新增更明确的工作台说明文案。

### 4. `ModelsWorkbenchHeader` 的处理方式

倾向：

- 不直接删除
- 但需要降级为共享 primitive 的薄包装，而不是继续作为独立 hero 组件存在

### 5. 哪些页允许完全删副标题

倾向：

- `模型 / 智能体 / 频道` 可以优先走极短副标题，必要时允许隐藏
- `技能 / 定时任务` 可以保留一句，但必须明显短于当前版本

### 6. `定时任务` 的智能体选择是否属于本轮

倾向：

- 属于产品语义必须项
- 但不属于单纯样式问题
- 只有在 `CronJobCreateInput / host route / gateway rpc` 同时支持 `agentId` 之后，才能算真正完成
