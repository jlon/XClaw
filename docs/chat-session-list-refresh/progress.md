## 已确认结论

- 聊天列表当前最主要的问题是网页感，不是功能缺失
- `QClaw` 值得学的是轻列表、弱 hover、去每行时间、弱动作暴露，以及默认单行 source list
- `XClaw` 自己更值得保留的是 inline 搜索和“仅在必要时才补多 Agent 区分”
- 这轮确认了“inline 搜索”也不意味着必须保留常驻 input；更像桌面的做法是先 trigger，再按需进入输入态
- 新确认的一点是：`XClaw` 当前偏 agent-list 感，并不是拿错数据，而是标题兜底和空主会话策略让真实会话被展示成了 agent-first 列表
- 新确认的另一个根因是：之前只修了拆分出的 `session-actions.ts`，但真实运行仍在走 `src/stores/chat.ts` 的旧 `newSession` 逻辑；这次已把真实入口与测试一并对齐
- 最新确认的一点是：不能只在 `ChatSessionsPane` 里隐藏内部会话。因为 `loadSessions` 会用 `sessions.list` 的首项决定当前会话，如果把 `cron/subagent` 留在 store 里，首屏仍然可能落到错误会话
- 这轮还确认了一个结构性教训：真正该共享的是“会话规范化逻辑”，不是事后靠两套实现分别补同样的 bug
- 最新确认的根因是：`QClaw` 的聊天页舒服，不只是因为灰度和圆角，更因为它没有独立的全局业务 rail；`XClaw` 之前这条 rail 会持续把聊天空间拖回“后台导航”心智
